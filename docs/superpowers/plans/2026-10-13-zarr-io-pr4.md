**Created:** 2026-10-13

Claims marked **[verified]** were checked by running code in the `iris-dev`
environment against zarr-python 3.4.1 while this plan was written; everything
else is read from source or from the spec.

**Goal:** Make `iris.load("store.zarr")` and
`iris.load("s3://bucket/store.zarr")` return cubes from a native Zarr version 2
or version 3 store, by implementing the `CFDataset` interface over zarr-python
and teaching Iris's load chain that a target can be a directory or a URL rather
than a seekable file.

**Architecture:** `iris/fileformats/zarr/_dataset.py` implements `CFDataset` and
`CFDatasetVariable` over a `zarr.Group` and its `zarr.Array`s, which is all the
CF layer from PR 2 and PR 3 needs in order to classify variables and build
cubes. There is no data proxy: `zarr.Array` is picklable, so `read_data` hands
it straight to `as_lazy_data` and adds CF decoding — masking, `valid_range`,
`scale_factor`/`add_offset` — as explicit `map_blocks` layers over the raw
array, implemented as pure functions in `_decode.py`. `iris/fileformats/zarr/
loader.py` is a thin `load_cubes` that opens a `ZarrDataset`, hands it to
`CFReader`, and runs the same `_load_cube` loop the netCDF loader runs.
`iris.io.load_stores` is the new entry point for a target that is not a file,
and a `ZarrStore` file element lets `FORMAT_AGENT` recognise one.

**Tech Stack:** Python 3.12–3.14, zarr-python ≥3.0.8, NumPy, Dask, pytest +
pytest-xdist, pre-commit (ruff, numpydoc, mypy, sort-all), `abc.ABC`,
`collections.abc.MutableMapping`.

**Spec:** [`../specs/2026-09-21-zarr-io-design.md`](../specs/2026-09-21-zarr-io-design.md)
— §2.4 lists the Zarr facts that shape the design, §3 the constraints agreed
before design, §4.1 the module layout, §4.2 the `CFDataset` interface, §4.4 the
whole of reading, §4.6 groups, §4.7 format detection and the load chain, §5's
fourth entry is this pull request, §6 the testing rules. The plan argues from
the spec; read both.

## Review Focus

Five failure modes the spec implies that **no task's own tests would otherwise
exercise**, most likely first. Each names the input or condition and the
behaviour a reasonable person expects; each has a test added to the task that
owns the code, written out in that task's own step style.

1. **A version 2 store's `_ARRAY_DIMENSIONS` attribute landing on the loaded
   cube.** It is how a version 2 store records dimension names, so under the
   §4.2 split it is a *property*, not a CF attribute — and every attribute a
   `CFVariable` does not consume reaches `cube.attributes`
   (`cf/loader.py::_add_unused_attributes`). Nothing in `_CF_ATTRS` excludes
   it, so unless `ZarrDatasetVariable.attributes` withholds it, every cube
   loaded from a version 2 store gains a stray `_ARRAY_DIMENSIONS` attribute
   and fails to compare equal to the same cube loaded from version 3. The user
   expects the two to be indistinguishable. → **Task 3, Step 9**, and
   **Task 13, Step 4** end to end.

2. **A store whose root group holds no arrays.** Spec §4.6 requires "a message
   that names the groups that do", and §7 records a real store in that shape —
   the ESA EOPF Sentinel-2 product, whose root holds only subgroups. The
   failure to defend against is not the message but its absence: an empty
   `CubeList` returned silently from `iris.load` of a store that plainly
   contains data is the worst available answer, and the one that falls out of
   writing the loop without thinking about it. → **Task 10, Step 2**.

3. **`iris.load("data/*")` matching a mix of `.nc` files and `.zarr`
   directories.** Spec §4.7 states the requirement and names the consequence —
   the file-or-store decision has to happen after glob expansion and before
   format dispatch. The quiet failure is partial: `_generate_cubes` partitions
   what `expand_filespecs` returns, so a bug that mis-partitions raises
   `IsADirectoryError` from `load_files` for the stores while the netCDF files
   load fine, and a user who did not expect the glob to match a store reads it
   as an Iris bug. → **Task 12, Step 2**.

4. **A `scale_factor` or `add_offset` that changes the result dtype.**
   `cf/loader.py::_get_actual_dtype` computes the post-unpacking dtype and the
   netCDF path gets the arithmetic itself from netCDF4. On the Zarr path Iris
   does the arithmetic, in `_decode.py`, so the dask array's declared dtype and
   what the decode layer actually produces are two separately-written
   statements that must agree. When they disagree dask does not complain: the
   graph is built, and the mismatch surfaces later as a wrong dtype on the
   cube, or as a `ValueError` from a downstream operation. A `uint16` band with
   `scale_factor = 0.0001` — the EOPF reflectance case in spec §7 — must give a
   `float64` cube whose lazy and realised dtypes match. → **Task 7, Step 11**.

5. **A `zarr` that is installed but too old, or not installed at all.** Spec §3
   requires "a clear `ImportError`" and §6 requires that "Iris without zarr
   installed must show no new failures". Two distinct paths reach a user here —
   `iris.load` of a `.zarr` target, and `import iris.fileformats.zarr` — and the
   second is the one that breaks the first rule by accident, because
   `iris.fileformats.__init__` imports every format module it registers. If the
   Zarr import is not deferred, installing Iris without zarr stops `import iris`
   working at all. → **Task 1, Steps 5–6**, and §6.3.

## 2. Findings that refine the spec

Checked while writing this plan. Each is either a correction the implementer
would otherwise hit as a failing test, or an answer the spec asked for.

**F1 — `zarr.Array` has no `dimension_names` property, and the error spec §2.4
quotes is a *write* error.** Version 3 names live at
`Array.metadata.dimension_names`. `create_array(..., dimension_names=…)` on a
version 2 group raises `ValueError: Zarr format 2 arrays do not support
dimension names.`, which is the message the spec cites — but **reading**
`ArrayV2Metadata.dimension_names` raises `AttributeError`, because the
attribute simply is not there **[verified]**. So `ZarrDatasetVariable.dimensions`
must branch on `metadata.zarr_format` and read `attrs["_ARRAY_DIMENSIONS"]` on
version 2. A `try: … except ValueError` would not catch anything.

**F2 — zarr-python rejects a wrong-length `dimension_names` at creation.**
`create_array(..., shape=(2, 2), dimension_names=("y",))` raises
``ValueError: `dimension_names` and `shape` need to have the same number of
dimensions`` **[verified]**. Spec §4.4 requires Iris to warn and load
anonymously for such a store, so the fixture for that test cannot be built
through the zarr-python API — it has to write `zarr.json` by hand.

**F3 — spec §12.3 Q2 is answered: `<U7` reads fine.** A fixed-length unicode
array creates, writes and reads back with its dtype intact on **both** version
2 and version 3 **[verified]**: `dtype('<U7')`, values
`array(['alpha', 'beta'], dtype='<U7')`. #6961's note that these are "not
strictly Zarr-supported" describes the specification, not zarr-python's
behaviour, and no special handling is needed. Close Q2 in spec §12.3 with this
answer.

**F4 — `Array.metadata.to_dict()` is JSON-serialisable as it stands.** No
`default=` fallback is needed, on either version **[verified]**. The version 3
key set is `attributes, chunk_grid, chunk_key_encoding, codecs, data_type,
dimension_names, fill_value, node_type, shape, storage_transformers,
zarr_format`; version 2's is `attributes, chunks, compressor,
dimension_separator, dtype, fill_value, filters, order, shape, zarr_format`.
A small array's key is ~460–520 characters, matching spec §4.4's estimate.

**F5 — zarr-python copies a store when it opens it read-only.** `WrapperStore`
implements `with_read_only` by constructing a new instance through
`_with_store`, so after `zarr.open_group(store=my_wrapper, mode="r")` the
array's store **is not** `my_wrapper` **[verified]**. An instrumented store
that counts bytes must therefore keep its tally in an object the copy shares,
and override `_with_store` to pass it on. A counter stored on the instance
reads zero and the test passes vacuously.

**F6 — the sharding read-unit result reproduces, but not its byte counts.** On
`shape=(1024,)`, `chunks=(8,)`, `shards=(1024,)` int32, reading the first eight
values **[verified]**: inner-chunk dask blocks fetch 2,052 bytes with or
without a decode layer; shard-sized blocks fetch 2,052 without one and **7,300
with** one. The shape of spec §4.4's table holds exactly — a `map_blocks` layer
defeats slice pushdown, so a shard-sized block materialises the whole shard —
but the absolute numbers differ from the spec's 2,084 / 6,148. They are
zarr-version-dependent. **The test compares its own two measurements; it must
not pin a literal byte count.**

**F7 — `_optimum_chunksize` sub-chunks a large store chunk, exactly as spec
§4.4 says.** `chunks=(8000, 8000)`, `shape=(16000, 16000)`, `f8` gives
`(2000, 8000)`; `chunks=(6000, 6000)`, `shape=(6000, 6000)`, `f8` gives
`(2000, 6000)` **[verified]**. Both are the real regression cases for the
alignment guard, and neither needs a store to reproduce.

**F8 — the errors zarr-python raises for the targets Iris will meet**
**[verified]**:

| target | exception |
|---|---|
| a path that does not exist | `FileNotFoundError` |
| a directory that is not a store | `zarr.errors.GroupNotFoundError` |
| `group=` naming a group that is not there | `zarr.errors.GroupNotFoundError` |
| `s3://…` with no s3fs installed | `ImportError: Install s3fs to access S3` |

The last is why spec §3's "Iris adds no dependency and handles no credentials"
costs nothing to honour: zarr-python's own message already tells the user what
to install.

**F9 — a read-mode `zarr.Array` refuses attribute writes** with
`ValueError: store was opened in read-only mode and does not support writing`
**[verified]**. `CFVariable` copies `data.attributes` into a plain `dict` at
construction (`cf/_variables.py::CFVariable.__init__`), so loading never writes
through — but `ZarrDatasetVariable.attributes` must still be a `MutableMapping`
to satisfy the interface, and its `__setitem__` will raise that `ValueError`
from zarr-python on a read-mode store. That is the right answer and needs no
wrapping.

**F10 — the shared `CFDataset` contract has to be split in two.**
`lib/iris/tests/unit/fileformats/cf/dataset/contract.py` holds one class whose
`writable` and `reopen` fixtures drive `populate()` through `create_dimension`,
`create_variable`, `__setitem__` and `write_handle`. Spec §5 puts the Zarr
write path in PR 6, so the whole write half is unrunnable here. Split
`CFDatasetContract` into `CFDatasetReadContract` and `CFDatasetWriteContract`;
`test_NetCDFDataset.py` inherits both and its coverage is unchanged; the new
Zarr test module inherits the read half, and PR 6 adds the other. Keeping one
class and skipping half of it would hide, behind a skip, the fact that an
implementation is incomplete — spec §6's whole argument for a shared body is
that divergence "fails loudly".

**F11 — `format` has to land here, not in PR 5.** Spec §5 assigns
`CFDataset.format` and `CFDataset.supports_dtype` to PR 5, but PR 4 merges
first and `ZarrDataset` cannot answer `ZARR_V2` versus `ZARR_V3` without it:
the version-aware masking split (§4.4) and the warnings this pull request
emits both need to name the format. `supports_dtype` is genuinely a saver
concern and stays in PR 5. **Add `format` here; record the move in spec §12.4
and amend §5's PR 4 and PR 5 entries.**

**F12 — `CFReader` cannot yet be handed an open `CFDataset`.**
`cf/_reader.py::CFReader.__init__` has two branches: a `str` opens a
`NetCDFDataset`, and anything else goes to `NetCDFDataset.from_existing`. A
`ZarrDataset` would be wrapped as a netCDF dataset and fail. PR 4 adds a third
branch that takes an already-open `CFDataset` and borrows it. Note that
`isinstance(file_source, CFDataset)` tests the **interface**, which is what
spec §4.2 requires generic code to do; the rule it forbids is testing an
implementation class.

**F13 — the marker files are where spec §4.7 says they are** **[verified]**. A
version 2 store's root directory holds `.zgroup` and `.zattrs`; a version 3
store's holds `zarr.json`. One `Path.is_file()` each.

**F14 — attribute values round-trip through `Array.attrs` untouched**, for a
nested object (`{'min': 1, 'max': 2}`), a numeric vector (`[1.0, 2.0]`) and
`float("nan")` **[verified]**. The read side of spec §4.4's nested-attribute
rule therefore needs no code at all: the value arrives as a `dict` or `list`
and is carried onto the cube. It needs a **test**, because "we do nothing" is
indistinguishable from "we never tried it".

**F15 — `Group.arrays()` yields only that group's own arrays**, and
`Group.group_keys()` lists its subgroups **[verified]**. Together they are
exactly spec §4.6: one group per call, and a root group with no arrays can name
the groups that have them.

**F16 — the `(name, size)` change does not have to reach
`_nc_load_rules/helpers.py`.** Four sites there match dimensions by name —
`helpers.py` lines near `build_auxiliary_coordinate`,
`build_dimension_coordinate`, `_add_cell_measures` and
`_add_ancillary_variables` — and `None in (None, "x")` is `True`, so an
anonymous dimension reaching them would attach a coordinate to the wrong cube
dimension. It cannot reach them: `CFReader._build_cf_groups` drops any variable
whose `spans` is `False` and promotes it to a data variable of its own, and
under the new rule a variable with any anonymous dimension spans nothing.
Dimension coordinates are safe for a second reason — `CFCoordinateVariable`
identifies on `nc_var_name in nc_var.dimensions`, which no anonymous dimension
satisfies. **Task 7 pins both claims with tests** rather than leaving them as
prose; without them this finding is the kind of comment that goes stale
unnoticed.

**F17 — `_CF_ATTRS_IGNORE` already covers the four attributes Iris consumes.**
`cf/_variables.py` seeds attribute tracking with
`{"_FillValue", "add_offset", "missing_value", "scale_factor"}`, described as
"handled by the netCDF4 module". On the Zarr path they are handled by
`zarr/_decode.py` instead, so the seeding stays correct and needs no change —
but the comment naming netCDF4 does, and `valid_min`/`valid_max`/`valid_range`
are deliberately **not** in that set, so they reach the cube on both paths.

**F18 — this pull request creates the first way to get a nested attribute onto
a cube, and the netCDF saver cannot write one.** Spec §4.4 says Iris carries a
JSON object or array attribute onto the cube and "does not write them back
through the netCDF saver"; spec §4.5 says checking attribute content before
saving is [#7329](https://github.com/SciTools/iris/issues/7329), out of scope.
Until then, `iris.load("store.zarr")` followed by `iris.save(cube, "out.nc")`
fails inside netCDF4, with a message naming neither the attribute nor the
cube. Nothing in this pull request can fix that without changing the netCDF
saver, which PR 5 relocates unchanged — so **Task 10 characterises it with a
test and Task 14 documents it**, which is the difference between a known
limitation and a surprise.

### Sequencing, and why it is this way

The order is: make a Zarr store answerable as a `CFDataset`, then make the CF
layer able to hold one, then make Iris able to find one.

1. **Tasks 1–7 build the Zarr dataset bottom-up** — dependency, interface,
   variable, group, contract, decoding, reading — and are testable without any
   of Iris's loading machinery. Each one ends with a store built in `tmp_path`
   and questions asked of it directly.
2. **Tasks 8–9 are the two changes to generic code.** They are separated from
   the Zarr work because they are the only parts a netCDF-only reviewer has to
   check, and because `spans` is the one place in this pull request where a
   mistake silently changes what loads from an existing netCDF file.
3. **Task 10 is the loader**, which can only be written once 1–9 exist.
4. **Tasks 11–12 are the load chain**, which is independent of everything above
   and could be reviewed by someone who knows nothing about Zarr. They come
   last among the code tasks because until Task 10 exists there is nothing for
   the chain to dispatch *to*.
5. **Tasks 13–15** are integration, documentation and the pull request.

The dependency that matters in the other direction is **PR 3**. This plan calls
`CFDatasetVariable.read_data`, `iris.fileformats.cf.loader._get_actual_dtype`,
`_LAZYVAR_MIN_BYTES` and `as_lazy_data(..., cache_key=...)`, none of which are

Three points about this shape are worth stating once, here, rather than
repeating in every task.

**`fill_value` means different things on the two backends, deliberately.**
`NetCDFDatasetVariable.fill_value` returns the `_FillValue` *attribute*;
`ZarrDatasetVariable.fill_value` returns `Array.fill_value`, the *storage*
field. On netCDF the two coincide. On Zarr they are different things (spec
§4.4), and conflating them masks every valid zero in an array that never
declared a sentinel. Nothing generic reads `fill_value` to decide masking —
`zarr/_decode.py::decode_parameters` does, and it reads the CF attributes
first.

**`encoding` is readable and never interpreted.** Generic code may print it,
record it, or hand it back to a user; it must not branch on a key. Its keys are
the backend's own spelling: `chunks`, `shards`, `codecs`, `zarr_format` for
Zarr; `chunksizes`, `zlib`, `complevel` for netCDF. `chunking` is the typed,
guaranteed member that the chunk calculation reads (spec §4.2).

**`cache_key` is a member of `ZarrDatasetVariable`, not of the interface.**
`read_data` is the only caller and both implementations build their own key —
netCDF from `repr(proxy)`, Zarr from the metadata document. Putting it on the
ABC would add a member no generic code reads, which is the indirection
`lib/iris/AGENTS.md` bans for a single caller.

```python
    names are written to the `_ARRAY_DIMENSIONS` attribute by hand - which is
    what xarray and NCZarr both do.
    """
    extra = {}
    if zarr_format == 3 and dimensions is not None:
        extra["dimension_names"] = dimensions
    array = group.create_array(
        name,
        shape=shape,
        dtype=dtype,
        chunks=chunks,
        shards=shards,
        fill_value=fill_value,
        **extra,
    )
    if zarr_format == 2 and dimensions is not None:
        array.attrs[ARRAY_DIMENSIONS] = list(dimensions)
    for key, value in (attributes or {}).items():
        array.attrs[key] = value
    return array


def make_store(path, *, zarr_format=3, chunks="auto", shards=None):
    """Write the canonical store at `path`, and return `path` as a string."""
    root = zarr.open_group(store=path, mode="w", zarr_format=zarr_format)
    for name, value in GLOBALS.items():
        root.attrs[name] = value

    array = make_array(
        root,
        "air_temperature",
        DATA.shape,
        "f8",
        zarr_format,
        dimensions=tuple(DIMENSIONS),
        chunks=chunks,
        shards=shards,
        fill_value=-1.0,
        attributes=VARIABLE_ATTRS,
    )
    array[:] = DATA

    # A dimensionless variable: what a grid mapping is, and the one shape a
    # CFDatasetVariable must handle without a leading dimension.
    scalar = make_array(
        root,
        "grid",
        (),
        "i4",
        zarr_format,
        dimensions=(),
        attributes={"grid_mapping_name": "latitude_longitude"},
    )
    scalar[()] = 0

    return str(path)
```

```python
# Copyright Iris contributors
#
# This file is part of Iris and is released under the BSD license.
# See LICENSE in the root of the repository for full licensing details.
"""The Zarr implementation of the :mod:`iris.fileformats.cf.dataset` interface.

This is the only module that knows both the CF interface and the zarr-python
API. Everything Zarr-specific the CF layer could want - where dimension names
are recorded, what a chunk is, what the store's own fill value is - either has
a named member on the interface or lives here as a Zarr-only member.

Three things about Zarr shape this module, and each is a trap if forgotten.

**A dimension name guarantees less than a netCDF one.** The version 3 core
specification makes ``dimension_names`` optional, allows a null entry, only
*recommends* that names are distinct within an array, and places no
restriction at all on reusing a name across arrays. All of that is conforming
Zarr, so none of it may raise. A dimension with no name is **anonymous**, which
Iris has always had: a cube dimension carrying no coordinate.

**``Array.fill_value`` is not ``_FillValue``.** It says what unwritten storage
reads back as; it does not say the value is missing. zarr-python defaults it to
zero, so reading it as a missing-value sentinel masks every valid zero in an
array that never declared one. :attr:`ZarrDatasetVariable.fill_value` reports
it as the storage fact it is, and the masking decision is made in
:mod:`iris.fileformats.zarr._decode` from the CF attributes.

**The read unit is the inner chunk, even when the array is sharded.** Zarr's
sharding codec is indexed, so a reader fetches only the inner chunks it needs.
:attr:`ZarrDatasetVariable.chunking` therefore returns ``Array.chunks``, never
``Array.shards``, and :func:`_align_chunks` aggregates upward into whole
multiples of it.

See sections 4.2, 4.4 and 4.6 of
``docs/superpowers/specs/2026-09-21-zarr-io-design.md``.

"""

from collections.abc import Iterator, Mapping, MutableMapping
from types import MappingProxyType
from typing import Any
import warnings

import numpy as np
import zarr

from iris.fileformats.cf.dataset import CFDataset, CFDatasetVariable
import iris.warnings

#: What :attr:`CFDataset.format` answers, by the store's Zarr version.
_FORMAT_BY_ZARR_VERSION = {2: "ZARR_V2", 3: "ZARR_V3"}

#: The version 2 attribute carrying dimension names, as xarray and NCZarr
#: write it. Storage, not a CF attribute, so it is withheld from `attributes`.
_ARRAY_DIMENSIONS = "_ARRAY_DIMENSIONS"


def _dimension_names(array) -> tuple:
    """Return one name or None per dimension of `array`.

    Parameters
    ----------
    array : :class:`zarr.Array`
        The array to read names from. Version 3 carries them in its metadata;
        version 2 carries them in the ``_ARRAY_DIMENSIONS`` attribute, which
        is a de-facto convention rather than part of the Zarr specification.

    Returns
    -------
    tuple
        Of length ``array.ndim``. ``None`` where the store names no dimension.

    Warns
    -----
    IrisCfLoadWarning
        If the store names a number of dimensions other than ``array.ndim``.
        The version 3 specification says the lengths "must" match, so such a
        store is malformed; its names are ignored and the array loads with
        anonymous dimensions.

    """
    anonymous = (None,) * array.ndim
    if not array.ndim:
        return ()

    if array.metadata.zarr_format == 3:
        names = array.metadata.dimension_names
    else:
        names = array.attrs.get(_ARRAY_DIMENSIONS)

    if names is None:
        return anonymous

    if len(names) != array.ndim:
        message = (
            "Ignoring malformed dimension_names, which names "
            f"{len(names)} dimensions of a {array.ndim}-dimensional array: "
            f"{array.basename}"
        )
        warnings.warn(message, category=iris.warnings.IrisCfLoadWarning)
        return anonymous

    return tuple(names)
```

```python
class ZarrDatasetVariable(CFDatasetVariable):
    """One array of a Zarr store, presented through the CF interface."""

    def __init__(self, array, location: str, format: str):
        """Wrap `array`.

        Parameters
        ----------
        array : :class:`zarr.Array`
            The array this variable presents.
        location : str
            The path or URL of the dataset this array belongs to.
        format : str
            ``ZARR_V2`` or ``ZARR_V3``, as its dataset reports.

        """
        self._array = array
        self._location = location
        self._format = format
        self._dimensions = _dimension_names(array)
        self._attributes = _ZarrAttributes(array, withhold={_ARRAY_DIMENSIONS})

    @property
    def name(self) -> str:
        """The array's name within its group."""
        return self._array.basename

    @property
    def location(self) -> str:
        """The path or URL of the dataset holding this variable."""
        return self._location

    @property
    def format(self) -> str:
        """``ZARR_V2`` or ``ZARR_V3``."""
        return self._format

    @property
    def dimensions(self) -> tuple:
        """One name per dimension, ``None`` where the store names none."""
        return self._dimensions

    @property
    def shape(self) -> tuple:
        """The array's shape."""
        return tuple(self._array.shape)

    @property
    def dtype(self) -> np.dtype:
        """The array's stored data type."""
        return self._array.dtype

    @property
    def size(self) -> int:
        """The total number of elements in the array."""
        return int(self._array.size)

    @property
    def fill_value(self) -> Any:
        """What unwritten storage reads back as. **Not** a missing-value flag.

        Version 3 requires this field, and zarr-python defaults it to zero, so
        it says nothing about whether a value is missing. The CF
        ``_FillValue`` and ``missing_value`` attributes say that, and
        :mod:`iris.fileformats.zarr._decode` reads them.

        """
        return self._array.fill_value

    @property
    def chunking(self) -> tuple | None:
        """The array's inner chunk shape, never its shard shape."""
        chunks = self._array.chunks
        return tuple(chunks) if chunks else None

    @property
    def encoding(self) -> Mapping:
        """The Zarr storage settings this array holds."""
        return MappingProxyType(
            {
                "chunks": self._array.chunks,
                "shards": self._array.shards,
                "codecs": self._array.metadata.to_dict().get("codecs"),
                "zarr_format": self._array.metadata.zarr_format,
            }
        )

    @property
    def attributes(self) -> MutableMapping:
        """The array's CF attributes, less the ones that are really storage."""
        return self._attributes

    def __getitem__(self, keys) -> np.ndarray:
        """Return the indexed portion of the array's data."""
        return self._array[keys]

    def __setitem__(self, keys, values) -> None:
        """Write `values` into the indexed portion of the array."""
        self._array[keys] = values

    def write_handle(self) -> "ZarrDatasetVariable":
        """Return self: a Zarr write target needs no proxy.

        ``zarr.Array`` is picklable and a chunk is an independent object in a
        key-value store, so there is no open file handle to avoid holding and
        no lock to acquire.

        """
        return self

    def __repr__(self) -> str:
        """Return a string representation."""
        return f"{self.__class__.__name__}({self.name!r}, {self.location!r})"

    # Zarr-only members below.

    @property
    def array(self):
        """The backing :class:`zarr.Array`. Nothing generic may read this."""
        return self._array
```

```python
class _ZarrAttributes(MutableMapping):
    """A Zarr node's attributes as a mapping, less the ones that are storage.

    ``_ARRAY_DIMENSIONS`` is how a version 2 store records dimension names.
    Under the interface's split that is a property, reported by
    :attr:`ZarrDatasetVariable.dimensions`, not a CF attribute - so it is
    withheld here. Leaving it in would put it on every cube loaded from a
    version 2 store, since every attribute the loading rules do not consume
    reaches ``cube.attributes``.
    """

    def __init__(self, node, *, withhold: frozenset = frozenset()):
        """Materialise the attributes of `node`, a zarr array or group."""
        self._node = node
        self._withhold = frozenset(withhold)
        self._values = {
            key: value
            for key, value in node.attrs.items()
            if key not in self._withhold
        }

    def __getitem__(self, key: str) -> Any:
        """Return `key`'s value."""
        return self._values[key]

    def __setitem__(self, key: str, value: Any) -> None:
        """Set `key`'s value, here and in the store."""
        if key in self._withhold:
            msg = f"Cannot set a storage attribute through `attributes`: {key}"
            raise KeyError(msg)
        self._node.attrs[key] = value
        self._values[key] = value

    def __delitem__(self, key: str) -> None:
        """Remove `key`, here and from the store."""
        del self._node.attrs[key]
        del self._values[key]

    def __iter__(self) -> Iterator[str]:
        """Return an iterator over the attribute names, in store order."""
        return iter(self._values)

    def __len__(self) -> int:
        """Return the number of attributes."""
        return len(self._values)

    def __repr__(self) -> str:
        """Return a string representation."""
        return f"{self.__class__.__name__}({self._values!r})"
```

```python
def _assemble_dimensions(variables) -> dict:
    """Return the dimension sizes the store's arrays agree on.

    Parameters
    ----------
    variables : mapping of str to :class:`ZarrDatasetVariable`
        Every array in one group.

    Returns
    -------
    dict
        Name to size, for every name used at exactly one size. Anonymous
        dimensions have no name and so are absent.

    Warns
    -----
    IrisCfLoadWarning
        For each name used at more than one size. Zarr places no restriction
        on reusing a name across arrays, so this is conforming and must not
        raise; merging the two would produce a wrong cube, so the name is
        omitted instead and the arrays that use it keep it in their own
        `dimensions`.

    """
    sizes: dict[str, int] = {}
    conflicts: dict[str, set[int]] = {}
    for variable in variables.values():
        for name, size in zip(variable.dimensions, variable.shape):
            if name is None:
                continue
            if name not in sizes:
                sizes[name] = size
            elif sizes[name] != size:
                conflicts.setdefault(name, {sizes[name]}).add(size)

    for name, found in conflicts.items():
        message = (
            "Ignoring a dimension name used at more than one size, "
            f"{sorted(found)}: {name}"
        )
        warnings.warn(message, category=iris.warnings.IrisCfLoadWarning)
        del sizes[name]

    return sizes
```

```python
#: What `mode` a dataset may be opened in. Writing is not implemented.
_READ_MODES = ("r",)

#: The one message every unimplemented write member raises.
_NO_SAVING = "Saving to Zarr is not supported."


class ZarrDataset(CFDataset):
    """A Zarr store, or one group of one, presented through the CF interface."""

    def __init__(self, location, mode: str = "r", *, group: str | None = None):
        """Open a Zarr store.

        Parameters
        ----------
        location : str or :class:`pathlib.Path`
            The store's path or URL. A URL is handed to zarr-python
            unaltered; Iris adds no store library and handles no credentials,
            so an unreachable scheme fails with zarr-python's own message.
        mode : str, default="r"
            Only ``"r"`` is supported.
        group : str, optional
            A ``/``-separated path to a group within the store. The root group
            by default. Iris reads one group per call and does not walk
            nested groups.

        Raises
        ------
        NotImplementedError
            For any `mode` other than ``"r"``.
        FileNotFoundError
            If `location` does not exist.
        zarr.errors.GroupNotFoundError
            If `location` is not a Zarr store, or holds no such `group`.

        """
        # Set first, so that close() is safe if opening fails.
        self._group = None
        self._closed = False
        self._variables: dict[str, ZarrDatasetVariable] | None = None
        self._attributes: _ZarrAttributes | None = None
        self._dimensions: dict[str, int] | None = None

        if mode not in _READ_MODES:
            raise NotImplementedError(f"{_NO_SAVING} Cannot open with mode={mode!r}.")

        self._mode = mode
        self._group_path = group
        target = str(location)
        self._location = target if group is None else f"{target.rstrip('/')}/{group}"

        self._group = zarr.open_group(store=target, mode=mode, path=group)
        self._format = _FORMAT_BY_ZARR_VERSION[self._group.metadata.zarr_format]

    @property
    def location(self) -> str:
        """The store's path or URL, with the group path when there is one."""
        return self._location

    @property
    def format(self) -> str:
        """``ZARR_V2`` or ``ZARR_V3``."""
        return self._format

    @property
    def mode(self) -> str:
        """The mode the store was opened in."""
        return self._mode

    @property
    def closed(self) -> bool:
        """Whether :meth:`close` has been called.

        A Zarr store is a namespace rather than an open file handle, so there
        is nothing to release and nothing else to ask.

        """
        return self._closed

    @property
    def variables(self) -> Mapping:
        """The group's arrays, by name. Arrays in subgroups are not included."""
        if self._variables is None:
            self._variables = {
                name: ZarrDatasetVariable(array, self._location, self._format)
                for name, array in self._group.arrays()
            }
        return self._variables

    @property
    def dimensions(self) -> Mapping:
        """The dimension sizes this group's arrays agree on."""
        if self._dimensions is None:
            self._dimensions = _assemble_dimensions(self.variables)
        return self._dimensions

    @property
    def encoding(self) -> Mapping:
        """The store-wide Zarr settings."""
        consolidated = self._group.metadata.consolidated_metadata
        return MappingProxyType(
            {
                "zarr_format": self._group.metadata.zarr_format,
                "consolidated": consolidated is not None,
            }
        )

    @property
    def attributes(self) -> MutableMapping:
        """The group's attributes."""
        if self._attributes is None:
            self._attributes = _ZarrAttributes(self._group)
        return self._attributes

    def create_dimension(self, name: str, size: int | None) -> None:
        """Raise: saving to Zarr is not supported."""
        raise NotImplementedError(_NO_SAVING)

    def create_variable(
        self, name: str, dtype, dimensions=(), *, fill_value=None, **encoding
    ):
        """Raise: saving to Zarr is not supported."""
        raise NotImplementedError(_NO_SAVING)

    def sync(self) -> None:
        """Do nothing: a Zarr write is not buffered."""

    def finalise(self) -> None:
        """Raise: saving to Zarr is not supported.

        A Zarr store's completion step is consolidating its metadata, which
        only a writer performs.

        """
        raise NotImplementedError(_NO_SAVING)

    def close(self) -> None:
        """Record that this dataset is finished with.

        A store is a namespace, not an open handle, so nothing is released.
        The flag exists because callers - :class:`iris.fileformats.cf.CFReader`
        among them - must be able to ask.

        """
        self._closed = True

    def __repr__(self) -> str:
        """Return a string representation."""
        return f"{self.__class__.__name__}({self.location!r}, mode={self.mode!r})"

    # Zarr-only members below.

    @property
    def subgroup_names(self) -> tuple:
        """The names of this group's subgroups.

        What the loader names when a group holds no data variables but the
        store plainly holds data elsewhere.

        """
        return tuple(self._group.group_keys())
```

```python
# Copyright Iris contributors
#
# This file is part of Iris and is released under the BSD license.
# See LICENSE in the root of the repository for full licensing details.
"""The CF decoding netCDF4 does for free and Zarr does not.

netCDF4 applies ``_FillValue``/``missing_value`` masking,
``valid_min``/``valid_max``/``valid_range`` masking and
``scale_factor``/``add_offset`` unpacking on every read. Zarr returns a plain
``numpy.ndarray`` and applies none of it, so these rules are implemented here.
They live on the Zarr side rather than in the shared CF layer because the
netCDF path gets the behaviour from the C library and has nothing to reuse.

Everything here is a pure function of values, with no store and no Dask in
sight. :func:`mask_and_scale` is what the loader lays over a raw array as a
``map_blocks`` layer - visible in the graph, fusable with its neighbours, and
testable on a plain ndarray.

Two traps, both from the Zarr specification rather than from CF.

**A floating ``_FillValue`` is base64 on version 3.** Released xarray encodes
it as base64 of a little-endian ``float64`` for *every* floating dtype,
including ``float32``, and its reader requires that form. It is the de-facto
encoding, not a producer's mistake, so Iris reads both it and a plain JSON
number. CF section 2.5.1 asks for "the scalar attribute with the name
``_FillValue`` and of the same type as its variable"; this is a deliberate,
narrow deviation, taken because interoperability with the other Zarr readers
is the reason for native Zarr support.

**``Array.fill_value`` is not a missing-value declaration.** It says what
unwritten storage reads back as, and zarr-python defaults it to zero. On
version 3 it is never a mask source: an ``int16`` array of ``[0, 1, 2]`` with
no CF attributes would otherwise load with its valid zero masked. On version 2
it is one, but only when no CF attribute is present, because version 2 stores
predate the convention - which is what released xarray's
``use_zarr_fill_value_as_mask`` does.

See section 4.4 of ``docs/superpowers/specs/2026-09-21-zarr-io-design.md``.

"""

import base64
import binascii
import struct
from typing import Any
import warnings

import numpy as np

import iris.warnings

#: The width of the base64 `_FillValue` encoding: one little-endian float64.
_PACKED_DOUBLE = "<d"
_PACKED_DOUBLE_BYTES = 8

#: The Zarr version whose stores predate the CF `_FillValue` convention, and
#: whose `Array.fill_value` is therefore read as a missing-value sentinel.
_FILL_VALUE_IS_A_MASK_BEFORE = 3


def decode_fill_value(value: Any, dtype: np.dtype, variable_name: str) -> Any:
    """Return a CF missing-value sentinel as a value of `dtype`.

    Parameters
    ----------
    value : Any
        The attribute's value, as the store holds it: a JSON number, or - for
        a floating variable - the base64 of a little-endian ``float64``.
    dtype : numpy.dtype
        The variable's own dtype. The result is narrowed to it, because a
        sentinel of a different width never equals anything in the array.
    variable_name : str
        Named in the warning, so the user can find the variable.

    Returns
    -------
    numpy.generic or None
        ``None`` when `value` is neither form, which is a producer error.

    Warns
    -----
    IrisCfLoadWarning
        When `value` cannot be read as a sentinel of `dtype`.

    """
    if isinstance(value, (bool, np.bool_)):
        # A JSON true/false is a number to Python and nothing to CF.
        decoded = None
    elif isinstance(value, (int, float, np.number)):
        decoded = value
    elif isinstance(value, str) and dtype.kind == "f":
        decoded = _decode_packed_double(value)
    else:
        decoded = None

    if decoded is None:
        message = (
            "Ignoring a missing-value attribute that is neither a number nor "
            f"the base64 of a float64, on variable {variable_name}: {value!r}"
        )
        warnings.warn(message, category=iris.warnings.IrisCfLoadWarning)
        return None

    return dtype.type(decoded)


def _decode_packed_double(value: str) -> float | None:
    """Return the float in a base64 little-endian float64, or None."""
    try:
        raw = base64.b64decode(value, validate=True)
    except (binascii.Error, ValueError):
        return None
    if len(raw) != _PACKED_DOUBLE_BYTES:
        return None
    return struct.unpack(_PACKED_DOUBLE, raw)[0]
```

```python
def decode_parameters(
    attributes,
    *,
    dtype: np.dtype,
    storage_fill_value: Any,
    zarr_format: int,
    variable_name: str,
) -> dict:
    """Return the CF decode parameters for one variable.

    Parameters
    ----------
    attributes : mapping
        The variable's CF attributes.
    dtype : numpy.dtype
        The variable's stored dtype, before any unpacking.
    storage_fill_value : Any
        ``zarr.Array.fill_value`` - what unwritten storage reads back as. A
        mask source only on version 2, and only when the variable declares no
        CF missing-value attribute.
    zarr_format : int
        2 or 3. The one place the version changes what is decoded.
    variable_name : str
        Named in any warning.

    Returns
    -------
    dict
        The keyword arguments :func:`mask_and_scale` takes, always with the
        same keys. :func:`decoding_required` says whether they do anything.

    """
    sentinels = []
    for name in ("_FillValue", "missing_value"):
        if name in attributes:
            decoded = decode_fill_value(attributes[name], dtype, variable_name)
            if decoded is not None:
                sentinels.append(decoded)

    if (
        not sentinels
        and zarr_format < _FILL_VALUE_IS_A_MASK_BEFORE
        and storage_fill_value is not None
    ):
        sentinels.append(storage_fill_value)

    valid_min = attributes.get("valid_min")
    valid_max = attributes.get("valid_max")
    valid_range = attributes.get("valid_range")
    if valid_range is not None and len(valid_range) == 2:
        valid_min, valid_max = valid_range

    scale_factor = attributes.get("scale_factor")
    add_offset = attributes.get("add_offset")

    return {
        "sentinels": tuple(sentinels),
        "valid_min": valid_min,
        "valid_max": valid_max,
        "scale_factor": scale_factor,
        "add_offset": add_offset,
        "dtype": _unpacked_dtype(dtype, scale_factor, add_offset),
    }


def _unpacked_dtype(dtype, scale_factor, add_offset) -> np.dtype:
    """Return the dtype the unpacked values will have.

    The same calculation as
    :func:`iris.fileformats.cf.loader._get_actual_dtype`, done here on plain
    values so that the dtype the Dask graph declares and the dtype the decode
    layer produces are one statement rather than two.
    """
    probe = np.zeros(1, dtype=dtype)
    if scale_factor is not None:
        probe = scale_factor * probe
    if add_offset is not None:
        probe = add_offset + probe
    return probe.dtype


def decoding_required(parameters: dict) -> bool:
    """Whether these parameters would change anything.

    A variable with nothing to decode gets no ``map_blocks`` layer and an
    unmasked Dask meta. Adding a masked meta without a layer beneath it would
    be a meta that lies about its own graph.
    """
    if parameters["sentinels"]:
        return True
    return any(
        parameters[name] is not None
        for name in ("valid_min", "valid_max", "scale_factor", "add_offset")
    )
```

```python
def mask_by_sentinels(block: np.ndarray, sentinels: tuple) -> np.ndarray:
    """Return a boolean mask of the elements equal to any sentinel.

    A NaN sentinel is matched with :func:`numpy.isnan`, because NaN does not
    equal itself and NaN is what nearly every version 3 store's base64
    ``_FillValue`` decodes to.
    """
    mask = np.zeros(block.shape, dtype=bool)
    for sentinel in sentinels:
        if isinstance(sentinel, (float, np.floating)) and np.isnan(sentinel):
            mask |= np.isnan(block)
        else:
            mask |= block == sentinel
    return mask


def mask_by_valid_range(block: np.ndarray, valid_min, valid_max) -> np.ndarray:
    """Return a boolean mask of the elements outside the valid range."""
    mask = np.zeros(block.shape, dtype=bool)
    if valid_min is not None:
        mask |= block < valid_min
    if valid_max is not None:
        mask |= block > valid_max
    return mask


def unpack(block: np.ndarray, scale_factor, add_offset, dtype: np.dtype) -> np.ndarray:
    """Return `block` unpacked by CF's scale and offset, as `dtype`."""
    result = block
    if scale_factor is not None:
        result = scale_factor * result
    if add_offset is not None:
        result = add_offset + result
    return result.astype(dtype, copy=False)


def mask_and_scale(
    block: np.ndarray,
    *,
    sentinels: tuple,
    valid_min,
    valid_max,
    scale_factor,
    add_offset,
    dtype: np.dtype,
) -> np.ma.MaskedArray:
    """Apply the CF decode rules to one block, in CF's order.

    Masking first, on the **packed** values, because CF declares a sentinel to
    be "of the same type as its variable"; unpacking second. The result is
    always a masked array, so that every block matches the Dask meta the
    loader declares for the layer.

    Parameters
    ----------
    block : numpy.ndarray
        One Dask block of the raw stored values.
    sentinels : tuple
        Values meaning "missing", already narrowed to the stored dtype.
    valid_min, valid_max : optional
        CF's valid range. Values outside it are masked.
    scale_factor, add_offset : optional
        CF's packing. ``value * scale_factor + add_offset``.
    dtype : numpy.dtype
        The dtype of the result, which the Dask graph has already declared.

    Returns
    -------
    numpy.ma.MaskedArray

    """
    mask = mask_by_sentinels(block, sentinels)
    mask |= mask_by_valid_range(block, valid_min, valid_max)
    return np.ma.masked_array(
        unpack(block, scale_factor, add_offset, dtype), mask=mask
    )
```

  module function `_align_chunks(chunks, store_chunks, shape, dtype,
  dims_fixed, name)`.

Three spec rules meet here.

**No proxy.** `zarr.Array` is picklable, a chunk is an independent object in a
key-value store, and a store is a namespace rather than an open handle, so
every reason `NetCDFDataProxy` exists is absent. The array goes to
`as_lazy_data` directly.

**Alignment aggregates upward only.** `_optimum_chunksize` expands a small
store chunk to a whole multiple, which is right; but when the store chunk is
*larger* than dask's target it shrinks below it, and subdividing a Zarr chunk
buys nothing — a read of any part of one fetches and decompresses the whole
object (F7 has the two reproductions). So the computed chunking is rounded
**up** to a whole multiple of the store chunk, never below, and the variable
warns when the store's own chunking exceeds the dask target.

**The key carries the metadata, not just the address.** `CACHE` is a
process-wide `LRUCache(100)`, so an address goes stale the moment a store is
rewritten in place.

```python
def _fixed_flags(dims_fixed, ndim: int) -> tuple:
    """Return one "do not change this" flag per dimension.

    `iris.fileformats.cf.loader._chunks_from_chunk_control` answers ``(None,)``
    when nothing is fixed, whatever the rank, so a length that does not match
    means nothing is fixed.
    """
    if dims_fixed is None or len(dims_fixed) != ndim:
        return (False,) * ndim
    return tuple(bool(flag) for flag in dims_fixed)


def _align_chunks(
    chunks: tuple,
    store_chunks: tuple | None,
    shape: tuple,
    dtype: np.dtype,
    dims_fixed,
    name: str,
) -> tuple:
    """Round `chunks` up to whole multiples of the store's own chunk shape.

    A Zarr chunk is the atomic unit of storage: reading any part of one
    fetches and decompresses the whole object. So a Dask chunking that
    subdivides the store's costs a re-read per subdivision - and over a remote
    store, one HTTP GET per subdivision for the same object. Aggregating
    upward costs nothing, because peak memory per task is a whole decompressed
    store chunk either way.

    Parameters
    ----------
    chunks : tuple of int
        The chunking computed for this variable, already through
        :func:`iris._lazy_data._optimum_chunksize`.
    store_chunks : tuple of int, optional
        The store's own chunk shape. ``None`` for an unchunked store, which
        constrains nothing.
    shape : tuple of int
        The variable's full shape. A result is never larger than this.
    dtype : numpy.dtype
        The stored dtype, for deciding whether one store chunk already exceeds
        Dask's target chunk size.
    dims_fixed : sequence of bool, optional
        Dimensions an explicit ``CHUNK_CONTROL`` setting pinned. These are
        left exactly as given: the keyword is an instruction, not a
        suggestion.
    name : str
        The variable's name, for the warning.

    Returns
    -------
    tuple of int

    Warns
    -----
    IrisLoadWarning
        When the result cannot tile the store grid without subdividing it -
        either because one store chunk already exceeds Dask's target size, so
        the store's layout is the binding constraint, or because an explicit
        setting subdivides it.

    """
    if store_chunks is None:
        return tuple(chunks)

    fixed = _fixed_flags(dims_fixed, len(shape))
    aligned = []
    subdivided = False
    for size, store_size, extent, is_fixed in zip(chunks, store_chunks, shape, fixed):
        if is_fixed:
            aligned.append(size)
            subdivided |= size < store_size
            continue
        whole = -(-size // store_size) * store_size
        aligned.append(min(whole, extent))
        subdivided |= whole > extent and extent % store_size != 0

    if _store_chunk_exceeds_dask_target(store_chunks, dtype):
        subdivided = True

    if subdivided:
        message = (
            "A Zarr chunk is read whole, so this store's chunking is the "
            "binding constraint on memory per task rather than Dask's target "
            f"chunk size: {name}"
        )
        warnings.warn(message, category=iris.warnings.IrisLoadWarning)

    return tuple(aligned)


def _store_chunk_exceeds_dask_target(store_chunks: tuple, dtype: np.dtype) -> bool:
    """Whether one whole store chunk is larger than Dask's target chunk size."""
    target = dask.utils.parse_bytes(dask.config.get("array.chunk-size"))
    return int(np.prod(store_chunks)) * dtype.itemsize > target
```

```python
    def read_data(self, chunking_policy):
        """Return this array's data, lazily where a lazy array is worth it.

        Parameters
        ----------
        chunking_policy : callable
            Called with no arguments, returning the ``(chunks, dims_fixed)``
            pair to build a lazy array with. Called only once the result is
            known to be lazy.

        Returns
        -------
        numpy.ndarray, numpy.ma.MaskedArray or dask.array.Array
            Real data for a small array, lazy data otherwise. Masked whenever
            the variable declares anything to decode.

        Notes
        -----
        There is no data proxy. ``zarr.Array`` is picklable, a chunk is an
        independent object in a key-value store so concurrent reads need no
        lock, and a store is a namespace rather than an open file handle. CF
        decoding is a ``map_blocks`` layer over the raw array rather than
        something hidden inside ``__getitem__``, so it is visible in the
        graph and testable without a store.

        """
        # Deferred, and the module rather than its members: the CF package
        # reaches this one through iris.fileformats.zarr.loader, so a
        # module-level import would be a cycle; and the tests patch
        # _LAZYVAR_MIN_BYTES on the module object.
        from iris.fileformats.cf import loader

        parameters = _decode.decode_parameters(
            self._attributes,
            dtype=self.dtype,
            storage_fill_value=self.fill_value,
            zarr_format=self.zarr_format,
            variable_name=self.name,
        )
        decoding = _decode.decoding_required(parameters)

        if self.size * self.dtype.itemsize < loader._LAZYVAR_MIN_BYTES:
            # A lazy array would cost more memory AND more time to access.
            block = np.asanyarray(self._array[...])
            if decoding:
                return _decode.mask_and_scale(block, **parameters)
            return block

        chunks, dims_fixed = chunking_policy()
        raw_meta = np.empty((0,) * self.ndim, dtype=self.dtype)

        if chunks == "auto":
            # CHUNK_CONTROL.as_dask(): the user asked for Dask's own policy,
            # so the store's layout is deliberately not consulted.
            lazy = as_lazy_data(
                self._array, chunks="auto", meta=raw_meta, cache_key=self.cache_key
            )
        else:
            chunks = _optimum_chunksize(
                chunks, shape=self.shape, dtype=self.dtype, dims_fixed=dims_fixed
            )
            chunks = _align_chunks(
                chunks, self.chunking, self.shape, self.dtype, dims_fixed, self.name
            )
            # Fixed in every dimension, because the alignment above is the
            # final word: as_lazy_data would otherwise re-run the
            # optimisation and undo it.
            lazy = as_lazy_data(
                self._array,
                chunks=chunks,
                meta=raw_meta,
                dims_fixed=(True,) * self.ndim,
                cache_key=self.cache_key,
            )

        if not decoding:
            return lazy

        return da.map_blocks(
            _decode.mask_and_scale,
            lazy,
            dtype=parameters["dtype"],
            meta=np.ma.masked_array(np.empty((0,) * self.ndim, parameters["dtype"])),
            **parameters,
        )
```

```python
class CountingStore(zarr.storage.WrapperStore):
    """Wrap a store, adding every byte it returns to a caller-owned tally.

    zarr-python copies a store when it opens it read-only, through
    `with_read_only` and `_with_store`, so a tally kept on the instance is
    never the one the live store writes to, and the test passes vacuously.
    """

    def __init__(self, store, tally):
        super().__init__(store=store)
        self.tally = tally

    def _with_store(self, store):
        return type(self)(store, self.tally)

    async def get(self, key, prototype, byte_range=None):
        buffer = await self._store.get(key, prototype, byte_range)
        if buffer is not None:
            self.tally.append(len(buffer))
        return buffer

    async def get_partial_values(self, prototype, key_ranges):
        buffers = await self._store.get_partial_values(prototype, key_ranges)
        self.tally.extend(len(b) for b in buffers if b is not None)
        return buffers


def bytes_to_read_first_chunk(location, dask_chunks):
    """Return the bytes fetched reading the first eight values of "v"."""
    tally = []
    store = CountingStore(zarr.storage.LocalStore(location), tally)
    array = zarr.open_group(store=store, mode="r")["v"]
    tally.clear()
    lazy = da.from_array(array, chunks=dask_chunks, meta=np.empty((0,), "i4"))
    lazy = da.map_blocks(
        lambda block: np.ma.masked_array(block), lazy, dtype="i4"
    )
    lazy[:8].compute()
    return sum(tally)


def test_a_sharded_array_is_read_by_the_inner_chunk(tmp_path):
    """Shard-sized Dask blocks fetch the whole shard, because of the layer.

    Bare Dask slicing can push a slice down into the array's own __getitem__,
    but a map_blocks layer in between cannot, so the block is materialised in
    full. The absolute byte counts are zarr-version-dependent; the comparison
    is not.
    """
    location = str(tmp_path / "sh.zarr")
    group = zarr.open_group(store=location, mode="w", zarr_format=3)
    array = group.create_array(
        "v", shape=(1024,), dtype="i4", chunks=(8,), shards=(1024,)
    )
    array[:] = np.arange(1024, dtype="i4")

    inner = bytes_to_read_first_chunk(location, 8)
    whole_shard = bytes_to_read_first_chunk(location, 1024)
    assert inner < whole_shard

    # And the variable chooses the inner chunk for exactly this reason.
    assert ZarrDataset(location).variables["v"].chunking == (8,)
```

```python
def build_netcdf(path, described):
    """Write `described` as a netCDF file and return its open dataset."""
    dataset = NetCDFDataset(path, mode="w")
```

```python
class _AnonymousDimension:
    """One dimension the store gives no name.

    A distinct instance per dimension, relying on object identity for
    equality, so that an anonymous dimension matches nothing: not a named
    dimension, not another anonymous one, and not itself as seen from a
    second variable. There is nothing to match on, so claiming a match would
    be invention.

    Zarr's version 3 core specification makes ``dimension_names`` optional and
    allows a null entry, so a conforming store can present this and it must
    not be an error. No netCDF variable ever has one.
    """

    def __repr__(self) -> str:
        return "<anonymous dimension>"
```

```python
    def _dimension_identities(self) -> tuple:
        """Return one hashable identity per dimension this variable spans.

        A named dimension's identity is the pair ``(name, size)``: two
        variables share a dimension when they name it identically *and* it is
        the same length in both. A name reused at two lengths links nothing,
        which is the only reading that cannot produce a wrong cube.

        equals nothing but itself.

        """
        return tuple(

            for name, size in zip(self.dimensions, self.shape)
```

```python
# Copyright Iris contributors
#
# This file is part of Iris and is released under the BSD license.
# See LICENSE in the root of the repository for full licensing details.
"""Load Iris cubes from Zarr stores.

.. z_reference:: iris.fileformats.zarr.loader
   :tags: topic_load_save

   API reference

A thin loop: open the store as a
:class:`~iris.fileformats.zarr._dataset.ZarrDataset`, hand it to
:class:`~iris.fileformats.cf.CFReader`, and build one cube per CF data
variable with :mod:`iris.fileformats.cf.loader` - the same machinery the
netCDF loader runs. Everything Zarr-specific happens below this module, in
:mod:`iris.fileformats.zarr._dataset`.

Iris loads **one** group per call. A Zarr store can legitimately hold
unrelated datasets, and merging them into one ``CubeList`` would be wrong, so
nested groups are not walked and ``group=`` selects which one to read.

UGRID meshes are not built here. :func:`iris.mesh.load_meshes` reaches a Zarr
store through the same format dispatch, but the mesh machinery lives in
:mod:`iris.fileformats.netcdf.ugrid_load` and this package does not import it.

See sections 4.6 and 4.7 of
``docs/superpowers/specs/2026-09-21-zarr-io-design.md``.

"""

from collections.abc import Iterable
import warnings

from iris.exceptions import TranslationError
from iris.fileformats.cf import CFReader
from iris.fileformats.cf.loader import (
    _actions_engine,
    _load_aux_factory,
    _load_cube,
    _translate_constraints_to_var_callback,
)
import iris.warnings

from ._dataset import ZarrDataset


def _check_has_data_variables(reader, dataset) -> None:
    """Raise if this group holds nothing to make a cube from.

    Returning an empty ``CubeList`` from a store that plainly holds data
    elsewhere leaves the user nothing to act on, and a store whose root group
    holds only subgroups is a real shape - the ESA EOPF Sentinel products are
    built that way.
    """
    if reader.cf_group.data_variables or reader.cf_group.promoted:
        return

    subgroups = dataset.subgroup_names
    if subgroups:
        message = (
            f"No data variables in Zarr group {dataset.location!r}. Load one "
            "of its groups instead, with the 'group' keyword: "
            f"{', '.join(sorted(subgroups))}"
        )
    else:
        message = f"No data variables in Zarr store {dataset.location!r}."
    raise TranslationError(message)


def load_cubes(file_sources, callback=None, constraints=None, group=None):
    """Load cubes from one or more Zarr stores.

    Parameters
    ----------
    file_sources : str or iterable of str
        The stores to load. A local directory path, or a URL that
        zarr-python can open - ``s3://``, ``gs://``, ``az://`` and ``abfs://``
        need the matching store library installed, which Iris does not
        depend on.
    callback : callable, optional
        Passed to :func:`iris.io.run_callback`.
    constraints : optional
        Used to skip data variables that cannot match, before they are built.
    group : str, optional
        A ``/``-separated path to a group within each store. The root group by
        default.

    Yields
    ------
    iris.cube.Cube

    Raises
    ------
    iris.exceptions.TranslationError
        If the selected group holds no data variables. The message names the
        store's other groups, when it has any.

    Notes
    -----
    This function maintains laziness; it does not realise data.

    """
    from iris.io import run_callback

    var_callback = _translate_constraints_to_var_callback(constraints)
    engine = _actions_engine()

    if isinstance(file_sources, str) or not isinstance(file_sources, Iterable):
        file_sources = [file_sources]

    for file_source in file_sources:
        with ZarrDataset(file_source, group=group) as dataset:
            with CFReader(dataset) as cf:
                _check_has_data_variables(cf, dataset)

                data_variables = list(cf.cf_group.data_variables.values()) + list(
                    cf.cf_group.promoted.values()
                )
                for cf_var in data_variables:
                    if var_callback and not var_callback(cf_var):
                        continue

                    cube = _load_cube(engine, cf, cf_var, cf.filename)

                    try:
                        _load_aux_factory(engine, cube)
                    except ValueError as exception:
                        warnings.warn(
                            str(exception),
                            category=iris.warnings.IrisLoadWarning,
                        )

                    cube = run_callback(callback, cube, cf_var, file_source)
                    if cube is None:
                        # The callback rejected it.
                        continue

                    yield cube
```

- Produces: `ZarrStore(FileElement)`; `iris.io.REMOTE_STORE_SCHEMES`;

  and the registered `"Zarr"` `FormatSpecification`, which Task 12 dispatches
  to.

Spec §4.7 sets the matching rule and forbids the obvious simplification:

> - **locally**, the target is a directory containing `zarr.json` (version 3)
>   or `.zgroup` (version 2);
> - **remotely**, the URI scheme is one of `s3`, `gs`, `az`, `abfs` and the
>   path ends in `.zarr`.
>
> **Do not add a third rule matching any path that ends in `.zarr`.** Joined by
> "or" it swallows the remote rule whole, leaving the scheme test unreachable.

One case the spec's prose does not spell out and the code must handle: the
format agent is asked about NCZarr URLs too, because `load_http` calls
`get_spec(url, None)` with the fragment still attached. A local NCZarr target
— `file:///path/store.zarr#mode=nczarr,file` — is a real Zarr store on disk, so
the marker-file test says yes unless the fragment is checked first. Spec §4.7's
claim that "the native reader and the NCZarr one are never candidates for the
same target" is true of what the *user* asked for, and this is what makes the
code agree with it.

```python
#: What a version 3 and a version 2 Zarr store put at the root of a store.
_ZARR_MARKERS = ("zarr.json", ".zgroup")


def _is_zarr_store(target):
    """Whether `target` names a native Zarr store.

    Locally the test is a marker file, which costs one stat and is what tells
    a real store from a directory someone named ``.zarr``. Remotely it is the
    scheme and the suffix, because reading a marker file would cost a network
    round trip before Iris knows it wants the target at all; a remote
    ``.zarr`` that turns out not to be a store fails when zarr-python opens
    it, with zarr-python's message.

    These are two tests for two kinds of target, not two chances for one. A
    third rule matching any path ending in ``.zarr`` would subsume the remote
    one and leave the scheme test unreachable.
    """
    if not isinstance(target, str):
        # iris.io.load_data_objects passes open datasets, not paths.
        return False

    scheme, part, fragment = decode_uri(target)
    if _is_nczarr_fragment(fragment):
        # The user asked for netCDF-c's Zarr driver by name. The store on
        # disk is a real one, so the local test below would otherwise claim it.
        return False

    if scheme in REMOTE_STORE_SCHEMES:
        return part.rstrip("/").endswith(".zarr")

    directory = Path(part)
    return any((directory / marker).is_file() for marker in _ZARR_MARKERS)


def _load_zarr(*args, **kwargs):
    """Load from Zarr stores, reporting clearly when zarr-python is absent."""
    try:
        from iris.fileformats.zarr import load_cubes
    except ImportError as exception:
        message = (
            "Unable to load a Zarr store - the 'zarr' package is not "
            "installed. Install zarr >=3.0.8, for example with "
            "'conda install -c conda-forge zarr'."
        )
        raise ImportError(message) from exception

    return load_cubes(*args, **kwargs)
```

```python
def load_stores(targets, callback, constraints=None):
    """Create a generator of Cubes from targets that are stores, not files.

    A store is a directory or a URL: something with no single seekable file
    to open, so :func:`load_files` cannot reach it and the format agent is
    asked without a buffer.

    Parameters
    ----------
    targets : iterable of str
        Local directory paths or remote URLs, already expanded.
    callback : callable
        Passed to the format handler.
    constraints : optional
        Passed to a constraint-aware format handler.

    Yields
    ------
    iris.cube.Cube

    Notes
    -----
    Typically, this function should not be called directly; instead, the
    intended interface for loading is :func:`iris.load`.

    """
    from iris.fileformats import FORMAT_AGENT

    handler_map = collections.defaultdict(list)
    for target in targets:
        handling_format_spec = FORMAT_AGENT.get_spec(target, None)
        handler_map[handling_format_spec].append(target)

    for handling_format_spec in sorted(handler_map):
        names = handler_map[handling_format_spec]
        if handling_format_spec.constraint_aware_handler:
            for cube in handling_format_spec.handler(names, callback, constraints):
                yield cube
        else:
            for cube in handling_format_spec.handler(names, callback):
                yield cube
```

```python
"""A version 3 store carrying the CF features a real one does.

Modelled on the NOAA GFS archive at dynamical.org, whose properties the Zarr
I/O design names as the ones worth exercising: version 3 `dimension_names`, a
sharded codec, a scalar grid-mapping variable, a two-dimensional auxiliary
coordinate, and the base64 `_FillValue` that released xarray writes for every
floating dtype. A cut-down copy of the real store replaces this.
"""

import base64
import struct

import numpy as np
import zarr

SHAPE = (2, 4, 6, 5)
DIMENSIONS = ("time", "level", "latitude", "longitude")


def float_fill_value(value):
    """Return `value` in the encoding released xarray writes for a float."""
    return base64.b64encode(struct.pack("<d", value)).decode("ascii")


def make_gfs_like_store(path):
    """Write the store and return its path as a string."""
    root = zarr.open_group(store=path, mode="w", zarr_format=3)
    root.attrs["Conventions"] = "CF-1.12"
    root.attrs["title"] = "A store shaped like a real one"
    root.attrs["license"] = "CC-BY-4.0"

    sizes = dict(zip(DIMENSIONS, SHAPE))
    for name, size in sizes.items():
        coordinate = root.create_array(
            name, shape=(size,), dtype="f8", dimension_names=(name,)
        )
        coordinate[:] = np.arange(size, dtype="f8")
    root["time"].attrs.update(
        {"units": "hours since 2000-01-01 00:00:00", "calendar": "standard"}
    )
    root["level"].attrs.update({"units": "hPa", "positive": "down"})
    root["latitude"].attrs.update({"units": "degrees_north", "axis": "Y"})
    root["longitude"].attrs.update({"units": "degrees_east", "axis": "X"})

    # A scalar grid mapping, as the GFS store's `spatial_ref` is.
    grid = root.create_array("spatial_ref", shape=(), dtype="i4")
    grid[()] = 0
    grid.attrs.update(
        {"grid_mapping_name": "latitude_longitude", "earth_radius": 6371229.0}
    )

    # A two-dimensional auxiliary coordinate, as the GFS store's valid_time is.
    valid_time = root.create_array(
        "valid_time",
        shape=SHAPE[:2],
        dtype="f8",
        dimension_names=DIMENSIONS[:2],
    )
    valid_time[:] = np.arange(np.prod(SHAPE[:2]), dtype="f8").reshape(SHAPE[:2])
    valid_time.attrs.update(
        {
            "units": "hours since 2000-01-01 00:00:00",
            "standard_name": "time",
            "statistics_approximate": {"min": 0.0, "max": 7.0},
        }
    )

    # The data variable: sharded, packed, with a base64 fill value.
    data = root.create_array(
        "temperature_2m",
        shape=SHAPE,
        dtype="i2",
        chunks=(1, 1, 3, 5),
        shards=(2, 4, 6, 5),
        dimension_names=DIMENSIONS,
        fill_value=-32768,
    )
    data[:] = np.arange(np.prod(SHAPE), dtype="i2").reshape(SHAPE)
    data.attrs.update(
        {
            "standard_name": "air_temperature",
            "units": "K",
            "scale_factor": 0.01,
            "add_offset": 273.15,
            # An integer variable's sentinel is a JSON number. The base64
            # encoding is for floating dtypes, and is on `pressure_surface`.
            "_FillValue": -32768,
            "coordinates": "valid_time",
            "grid_mapping": "spatial_ref",
        }
    )

    # A floating variable, carrying the base64 `_FillValue` that released
    # xarray writes for every floating dtype.
    flat_shape = SHAPE[:1] + SHAPE[2:]
    pressure = root.create_array(
        "pressure_surface",
        shape=flat_shape,
        dtype="f4",
        dimension_names=DIMENSIONS[:1] + DIMENSIONS[2:],
    )
    pressure[:] = np.arange(int(np.prod(flat_shape)), dtype="f4").reshape(flat_shape)
    pressure.attrs.update(
        {
            "standard_name": "surface_air_pressure",
            "units": "Pa",
            "_FillValue": float_fill_value(float("nan")),
            "grid_mapping": "spatial_ref",
        }
    )

    return str(path)
```

```rst
=========================
Zarr I/O Handling in Iris
=========================

.. readingtime::

`Zarr <https://zarr.dev/>`_ stores an array as many independently compressed
chunks under a prefix, rather than as one file. Iris reads Zarr version 2 and
version 3 stores natively, through
`zarr-python <https://zarr.readthedocs.io/>`_.

``zarr`` is an **optional dependency**. Install it to load Zarr stores::

    conda install -c conda-forge zarr

Iris without it behaves exactly as before, and raises an ``ImportError``
naming the package if you ask it to load a store.

Loading
-------

A store is a directory, or a URL, so pass it where you would pass a file::

    cubes = iris.load("/data/forecast.zarr")

Iris recognises a local store by the metadata file at its root - ``zarr.json``
for version 3, ``.zgroup`` for version 2 - not by the ``.zarr`` suffix, so a
directory that merely has the suffix is not mistaken for one.

Remote stores
-------------

A URL with one of the ``s3``, ``gs``, ``az`` or ``abfs`` schemes, ending in
``.zarr``, is passed to zarr-python unaltered::

    cubes = iris.load("s3://noaa-gfs-bdp-pds/forecast.zarr")

Iris adds no store library of its own and handles no credentials. Install the
one your scheme needs -- ``s3fs``, ``gcsfs``, ``adlfs`` -- and configure it as
that package documents. zarr-python raises an ``ImportError`` naming the
package if it is missing.

Groups
------

A Zarr store may hold several groups, and they need not describe the same
thing. Iris loads **one** group per call, like xarray, rather than merging
them: ``iris.load`` reads the root group, and a store whose root holds no data
variables raises a message naming the groups that do.

To read another group, call the Zarr loader directly::

    from iris.cube import CubeList
    import iris.fileformats.zarr

    cubes = CubeList(
        iris.fileformats.zarr.load_cubes(
            "/data/sentinel.zarr", group="measurements/reflectance/r10m"
        )
    )

Dimension names
---------------

A netCDF dimension has a name, one length, and a meaning shared across the
whole file. A Zarr dimension name is weaker in three ways, and all three are
permitted by the version 3 specification:

* an array need not name its dimensions at all;
* it may name some and not others;
* the same name in two arrays guarantees nothing -- not even the same length.

So Iris matches dimensions on the pair *(name, length)*. Two arrays share a
dimension when they name it identically **and** it is the same length in both.
A dimension with no name is **anonymous**, and never matches anything; the
cube simply has a dimension with no coordinate on it, which is an ordinary
Iris cube. A dimension name used at two different lengths is reported with a
warning and links nothing.

Version 2 stores have no dimension-name field, and carry names in an
``_ARRAY_DIMENSIONS`` attribute instead -- the convention xarray established.
Iris reads it, and does not pass it on to the cube.

Missing data
------------

Zarr applies no masking of its own, so Iris does it, from the CF attributes:
``_FillValue`` and ``missing_value`` for sentinels,
``valid_min``/``valid_max``/``valid_range`` for a range, and
``scale_factor``/``add_offset`` for packed data.

A Zarr array also has a ``fill_value`` in its metadata. This is **not** a
missing-value declaration: it says what a chunk that was never written reads
back as, and zarr-python defaults it to zero. Iris therefore ignores it as a
mask source on version 3, where it is a required field, and uses it on version
2 only when the array declares no CF attribute -- which is what version 2
writers meant by it, and what xarray does.

Chunking
--------

Iris chooses Dask chunks from the store's own chunking, as it does for netCDF,
and :data:`~iris.fileformats.cf.loader.CHUNK_CONTROL` works the same way for
both formats.

One rule is specific to Zarr. A Zarr chunk is the atomic unit of storage:
reading any part of one fetches and decompresses the whole object. So Iris
rounds the computed chunking **up** to a whole multiple of the store's
chunking, never below it. When a single store chunk is already larger than
Dask's target chunk size, the store's layout is the binding constraint on
memory per task, and Iris warns to say so.

A **sharded** array is chunked on its inner chunks, not its shards. Zarr's
sharding codec is indexed, so a reader fetches only the inner chunks it needs.

zarr-python fetches chunks concurrently, under its own
``zarr.config`` setting ``async.concurrency``. Iris does not change it. Dask's
worker count and that concurrency multiply, so a large Dask pool over a remote
store can open far more connections than either number suggests; if you are
rate-limited, lower one of them.

Attributes
----------

A Zarr attribute value may be any JSON literal, including a nested object or
an array of arrays, which CF cannot express at any rank. Iris carries such a
value onto the cube unchanged and does not interpret it. See
:issue:`7288` for the wider question of how the CF attribute model should map
onto JSON.

.. note::

    A cube carrying such an attribute **cannot be saved as netCDF**, because
    netCDF attribute values are scalars, strings and one-dimensional arrays.
    The failure comes from the netCDF library and does not name the attribute;
    see :issue:`7329`. Delete the attribute before saving::

        del cube.attributes["stac_discovery"]

NCZarr
------

Iris has long been able to read and write Zarr through netCDF-c's NCZarr
driver, by way of a URL fragment::

    iris.load("file:///data/forecast.zarr#mode=nczarr,file")

That is unchanged, and is still how you reach NCZarr. NCZarr implements Zarr
version 2 and writes scalar variables as length-one arrays; the native reader
described above handles both versions and is what a plain path or URL now
uses.
```
