**Goal:** Turn the 1721-line `iris.fileformats.cf` module into a package with a
re-exporting `__init__.py`, and land the unit test coverage that protects the
rewrite PR 2 will do to it — without changing any behaviour.

free to move in later pull requests.

numpydoc, mypy, sort-all), Sphinx with `sphinxcontrib.apidoc`, `git mv`.

## Review Focus

Five failure modes the spec implies that **nothing in this pull request's test
suite or hook set exercises**, most likely first. Each names the condition and
the behaviour a reasonable person expects; each has a test or gate added to the
commit that owns the code, written out in §6.4.

1. **A public name left out of `cf/__init__.py` or `__all__.`** Someone writes
   `from iris.fileformats.cf import CFMeasureVariable`, or a docstring writes
   `:class:`~iris.fileformats.cf.CFReader`` (there are two such in
   `docs/src/whatsnew/` alone **[verified]**), and expects it to resolve as it
   does today. Nothing checks this: ruff's whole `F` ruleset is off so F401
   never fires, `sort-all` only sorts what is already there, no test walks the
   surface, and the docs build has no `-W` **[verified]** — so the symptom is a
   silently empty API page rather than an error. → §6.4 test 1, commit 4.

2. **A name the moved code still needs, left behind in the module it came
   from.** `_reader.py` calls a helper that stayed in `_variables.py`, on a
   branch the suite never travels; the import succeeds and the `NameError`
   waits for a user's file. The linter that exists for exactly this — Pyflakes
   F821 — is in the project's ignore list **[verified]**. → §6.4 gate 2,
   commit 4. `ruff check --select F lib/iris/fileformats/cf.py` reports
   **`All checks passed`** today **[verified]**, so the baseline is zero and
   any finding after the cut was caused by the cut.

3. **An import left behind that the moved code no longer needs.** If
   `_variables.py` keeps `from iris.fileformats.netcdf import _bytecoding_datasets,
   _thread_safe_nc`, every test still passes and §5.3's claim that `_reader.py`
   is the only module coupled to `netcdf` is quietly false — which is the exact
   coupling spec §4.2 sends PR 2 to remove. F401 is off, so nothing says so.
   → §6.4 test 3, commit 4.

4. **`import iris.fileformats.cf` as the first import in a fresh
   interpreter.** A user or a downstream library imports the package before
   anything has imported `iris`, and expects it to work. The suite can never
   see this: pytest imports `iris` — and so `iris.fileformats.netcdf` — long
   before any cf test module is collected. The split adds a hop to the
   pre-existing `cf` ↔ `netcdf` cycle (§9.2). → §6.4 test 4, commit 4.

5. **Reaching a name that is now private.** `from iris.fileformats.cf import
   _CFFormulaTermsVariable` works today and deliberately stops working (§5.5),
   as do `cf._is_str_dtype`, `cf._getncattr` and `cf._CF_PARSE`. The decision
   is right — spec §4.1 says third-party code must not reach past the package —
   but it exists only as prose, so nothing stops a later pull request
   re-widening the surface by adding one convenient re-export. → §6.4 test 5,
   commit 4.

## 1. What this pull request is

Two things, in this order:

1. **Land the unit test coverage from [#7259](https://github.com/SciTools/iris/pull/7259)**
   (branch `cf_reader_zarr`, by @trexfeathers and @pp-mo) against today's

classes against `CFDataset`, the net that catches a regression did not move
with the thing it is testing. Landing the tests in the same pull request as the
split, rather than a separate one, is what lets a reviewer see the suite pass
before and after the move — see §4.

Neither half changes behaviour. The whole existing suite passes untouched.

### 3.2 `__all__` in `__init__.py` is load-bearing for the API docs

Not a style preference. `sphinx.ext.autodoc`'s `ModuleDocumenter` has two
branches **[verified against sphinx 8.1.3 in `iris-dev`]**:

```python
if self.__all__ is None:
    # for implicit module members, check __module__ to avoid
    # documenting imported objects
    return True, list(members.values())
```

After the split, every class's `__module__` is `iris.fileformats.cf._variables`
or `._reader`, not `iris.fileformats.cf`. Without `__all__`, autodoc takes the
first branch, the `__module__` check rejects all fifteen classes, and the
`iris.fileformats.cf` API page renders **empty**. With `__all__` present,
autodoc takes the other branch and skips only members *absent* from it, so the
re-exports are documented and no `imported-members` option is needed.

`iris.mesh` is the existing precedent for exactly this and declares `__all__`
for the same reason. §8 makes a docs build one of the verification steps, and
§6.4's first test pins the same property without needing one.

## 4. Commit sequence

Five commits, each green on its own.

### 4.0 What "green" means at every commit

Two gates, both run **before** the commit is made, never after:

```bash
git add <paths>
pre-commit run --files <paths>   # re-stage, repeat until clean
pytest -n auto <targets>
```

**`pre-commit` first, and in a loop.** The hooks rewrite files in place —
`ruff-check --fix`, `ruff-format` and `sort-all` all do — so a first run that
reports failures and a second that passes is the normal outcome, not a problem.
Re-stage and re-run until a full pass is clean, then commit. `AGENTS.md`
requires this, and the ISC001/COM812 interaction in its gotcha list is exactly
the case where a single run is not enough.

**Never `--no-verify`, and never defer the hooks to the end of the branch.** A
formatting fix applied three commits later lands in a diff that claims to be a
pure move, which destroys the one property that makes commit 3 reviewable
(§9.1). The hooks belong to the commit that caused them.

Commit 1 is markdown under `docs/superpowers/`, which is outside the global
`files:` regex in `.pre-commit-config.yaml` **[verified]** — every Python hook
reports "no files to check". Run it anyway: on a commit that should touch no
Python at all, that output *is* the check.

§8.2 lists which hooks have something to say at which commit, and why.

### 5.4 Where `reference_terms` goes, and why it matters

The spec does not say. It is a public name — a CF Appendix D constant table
carrying `#:` doc comments — with exactly two consumers: `CFReader` at
cf.py:1672, and `_nc_load_rules/actions.py:628` through the package.

It goes in **`_reader.py`**, with its only in-package consumer. The deciding
argument is not tidiness but a test in the incoming suite:
`test_CFReader.py:815` does `mocker.patch("iris.fileformats.cf.reference_terms")`.
Patching rebinds a *module global*; it only affects the reader if it patches
the module the reader's own global lookup resolves against. Put
`reference_terms` in `_variables.py` and have `_reader.py` do
`from ._variables import reference_terms`, and patching `cf._variables.reference_terms`
would silently fail to affect `CFReader` — a test that passes while testing
nothing. Co-locating it makes `cf._reader.reference_terms` the one true
binding.

```python
# Copyright Iris contributors
#
# This file is part of Iris and is released under the BSD license.
# See LICENSE in the root of the repository for full licensing details.
"""Unit tests for the public surface of :mod:`iris.fileformats.cf`.

The package is a re-export layer over a private file layout, so what needs
testing is the layer itself: that it exposes everything it used to, exposes
nothing it should not, and imports cleanly on its own.
"""

import subprocess
import sys
from types import ModuleType

import pytest

import iris.fileformats.cf as cf
from iris.fileformats.cf import _group, _reader, _variables

PRIVATE_MODULES = (_variables, _group, _reader)


def _origin(value, fallback):
    """Return the module path a name came from, for values and modules alike."""
    if isinstance(value, ModuleType):
        return value.__name__
    return getattr(value, "__module__", fallback)


def _defined_public_names(module):
    """Return the public names a module defines itself, ignoring imports."""
    return {
        name
        for name, value in vars(module).items()
        if not name.startswith("_")
        and not isinstance(value, ModuleType)
        and _origin(value, module.__name__) == module.__name__
    }


@pytest.mark.parametrize("module", PRIVATE_MODULES, ids=lambda m: m.__name__)
def test_public_names_are_re_exported(module):
    # Review Focus 1. A name defined in a private module and left out of
    # __all__ vanishes from the API docs without any warning, because autodoc
    # rejects it on __module__ - see the plan, section 3.2.
    assert _defined_public_names(module) <= set(cf.__all__)


@pytest.mark.parametrize("name", cf.__all__)
def test_all_entries_resolve(name):
    # Review Focus 1, the other direction: a name in __all__ that the package
    # cannot supply breaks "from iris.fileformats.cf import *" and the docs.
    assert hasattr(cf, name)


@pytest.mark.parametrize("module", (_variables, _group), ids=lambda m: m.__name__)
def test_only_the_reader_is_coupled_to_netcdf(module):
    # Review Focus 3. Confining the netCDF import to _reader is the whole
    # point of the split; F401 is disabled here, so a stale import left
    # behind by the cut would otherwise go unremarked.
    coupled = {
        name
        for name, value in vars(module).items()
        if _origin(value, "").startswith("iris.fileformats.netcdf")
    }
    assert coupled == set()


@pytest.mark.parametrize(
    "first_import",
    ["iris.fileformats.cf", "iris.fileformats.netcdf"],
)
def test_imports_in_a_fresh_interpreter(first_import):
    # Review Focus 4. cf and netcdf import each other, and the split adds a
    # hop to that cycle. pytest has already imported iris by the time this
    # module is collected, so a new process is the only way to see it.
    code = f"import {first_import}\nimport iris.fileformats.cf"
    completed = subprocess.run(
        [sys.executable, "-c", code],
        capture_output=True,
        text=True,
    )
    assert completed.returncode == 0, completed.stderr


@pytest.mark.parametrize(
    "name",
    ["_CFFormulaTermsVariable", "_is_str_dtype", "_getncattr", "_CF_PARSE"],
)
def test_private_names_are_not_re_exported(name):
    # Review Focus 5. These were reachable on the flat module and are
    # deliberately not reachable on the package - spec section 4.1.
    assert not hasattr(cf, name)
```

## 9. Risks

### 9.1 A move that is not a move

**The risk:** an accidental edit inside 1721 relocated lines — a lost line
during the cut, a mangled decorator, a constant redefined in two modules.

**Why it is low:** commit 3 is a `git mv` that `git` records as `R100`, so
only commit 4's cut can introduce one, and that commit moves two contiguous
blocks with a hard boundary each (`class CFGroup` at 1116, `class CFReader` at
1279).

**How we would know:** check 7 in §8 — the additions and deletions must balance.
A block lost in the cut shows as an unexplained deletion, and the suite from
commit 2 covers all three seams.

### 9.2 Import cycles

`iris.fileformats.cf` and `iris.fileformats.netcdf` already import each other
at module level today: `cf.py:35` takes `_bytecoding_datasets` and
`_thread_safe_nc` from `netcdf`, while `netcdf/loader.py:43`, `saver.py:64` and
`_nc_load_rules/helpers.py:38` import `cf`. It works because the consumers
resolve the names at call time, not import time — the one import that would
bite, `from iris.fileformats.cf import CFBoundaryVariable` in `helpers.py:49`,
is under `TYPE_CHECKING` **[verified]**.

**What the split changes:** one more hop. `cf/__init__.py` executes
`._variables` (which imports neither `netcdf` nor `hh` — §3.3), then `._group`,
then `._reader`, which is where the `netcdf` import now happens. So the cycle
is entered *later* than today, not earlier. `_variables.py` does still pull
`iris.mesh.components`, which executes `iris.mesh/__init__.py`, which imports
`iris.fileformats.netcdf.saver` — the same cycle `cf.py` has today at the same
point.

**How we would know:** check 4 in §8 — both import orders in a fresh
interpreter:

```bash
python -c "import iris.fileformats.cf"
python -c "import iris.fileformats.netcdf"
python -c "import iris.mesh"
python -c "import iris"
```

A cycle failure is deterministic and loud, so this is cheap insurance rather
than a real worry.

## 10. The dead branch at `cf.py:1663`

The #7259 branch adds one non-test line, a `# TODO` comment against:

```python
for cf_var in self.cf_group.formula_terms.values():
    if iris.FUTURE.derived_bounds:
        if self.cf_group[cf_var.cf_name] is CFBoundaryVariable:
            continue
```

The TODO is right, and the finding is stronger than "is this supposed to be an
`isinstance()`?" — `CFGroup.__getitem__` yields a `CFVariable` **instance**, so
`is CFBoundaryVariable`, which compares it to the **class**, can never be true.
The `continue` has never executed. The guard that `iris.FUTURE.derived_bounds`
was meant to install is absent.

**This pull request does not fix it.** Spec §5 declares PR 1 "no behaviour
change and no API change", and changing `is` to `isinstance` alters what loads
under `iris.FUTURE.derived_bounds` — it needs its own tests, its own reviewer
attention and a `bugfix` changelog fragment, none of which belong in a move.

**What it does instead:** raise a GitHub issue against `SciTools/iris`
describing the finding, and carry the comment forward rewritten to cite it, per
`lib/iris/AGENTS.md`'s rule that a non-obvious finding links to its source.
The issue is
[#7296](https://github.com/SciTools/iris/issues/7296), raised 2026-09-23, and
it records the provenance: the branch was introduced by #6481
(`Pp derived bounds`, 2025-06-02) **[verified]**.

```python
if iris.FUTURE.derived_bounds:

    if self.cf_group[cf_var.cf_name] is CFBoundaryVariable:
```
