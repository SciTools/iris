**Goal:** Move the format-agnostic half of the netCDF saver into `iris.fileformats.cf.saver`, leaving `iris.fileformats.netcdf.saver` holding netCDF's entry points, its keyword vocabulary and four netCDF-only hooks, so that PR 6 can add Zarr saving by subclassing one class.

**Architecture:** Today `netcdf/saver.py` is one 3178-line module that mixes the CF data model (dimension naming, coordinate and mesh variables, grid mappings, cell methods, attribute compliance) with netCDF4's own vocabulary (`zlib`, `endian`, `|S1` char dimensions, NCZarr URLs, the ncdata bridge). PR 2 already pushed the storage calls behind `CFDataset`, so most of the class no longer names netCDF at all. This plan extracts the five places that still do, as named hooks on the class, then `git mv`s the file to `cf/saver.py` and renames the class to `CFSaver`. `iris.fileformats.netcdf.saver.Saver` becomes a subclass that supplies the netCDF hooks and keeps today's signature exactly.

**Tech Stack:** Python 3.12–3.14, NumPy, Dask, netCDF4 (via `iris.fileformats.netcdf._thread_safe_nc`), pytest + pytest-mock, pre-commit (ruff, numpydoc, mypy, sort-all, and the repository's local hooks), Sphinx.

## Review Focus

Five things the spec implies, that no existing test exercises, and that would bite
a real user. Each is pinned by a test in the task named.

1. **`supports_dtype` changes which dtypes get cast down.** Today's guard fires only
   for int64 and unsigned integers, and only when `file_format` is one of three
   strings. Two ways to get this wrong, and both are silent. Answering `False` more
   widely sends some other dtype into the `astype(np.int32)` branch below, which
   truncates a float. Answering `False` *correctly* for `NETCDF3_64BIT` turns
   today's crash on that format into a successful save, which is a behaviour change
   this pull request may not make (F3). → **Task 1, Steps 1–2 and 11–12**:
   `test_an_int64_cube_saves_as_today` runs all four netCDF formats and records what
   each does now, including the crash, and `test_a_dtype_the_format_holds_is_never_cast`
   runs the five dtypes the saver actually writes against all four formats.
2. **A method quietly loses its name in the move.** `Saver` is driven from outside
   Iris: the emulated-variable branch exists so that ncdata can hand the saver its
   own dataset-like objects (issue #4994, "Xarray bridge"), and the class is public
   API that third parties subclass. Every method this plan moves to `CFSaver` keeps
   its name, so an override keeps overriding. Nothing today would notice if one
   were renamed or dropped along the way. → **Task 4, Steps 11–12**:
   `test_the_netcdf_saver_still_answers_every_method_it_answers_today` compares the
   full public and underscore method inventory against a list recorded before the
   move.
3. **Lazy data silently vanishes from an NCZarr save.** NCZarr cannot be reopened
   for deferred writes, so `Saver.__exit__` flushes `_nczarr_writes` before closing.
   A missing chunk in a Zarr store is not an error on read: it comes back as the
   fill value with no warning (spec §4.5). If the flush is left behind in `CFSaver`
   while `_is_nczarr` moves to the subclass, or the reverse, the save succeeds and
   the data is gone. → **Task 3, Steps 5–6**:
   `test_lazy_data_reaches_an_nczarr_target` saves a lazy cube to an NCZarr URL and
   reads the values back.
4. **`cf_patch` receives the wrong objects.** `iris.site_configuration["cf_patch"]`
   is a hook documented since Iris 1.3 as receiving netCDF4 objects. Handing it a
   `CFDataset` would not raise: `CFVariable` defines no `__setattr__`, so
   `variable.name = value` inside a user's hook would succeed and write nothing. →
   **Task 3, Steps 9–10**: `test_cf_patch_receives_raw_netcdf4_objects` asserts the
   types of both arguments the hook is called with.
5. **Importing the saver from the loader at module scope closes a loop.**
   `cf/loader.py` reaches into the saver twice, deferred, with a comment saying
   they stay that way until this pull request. Making them module-scope puts
   `cf.saver` inside a chain that already runs `cf/__init__` → `_reader` →
   `netcdf/_dataset` → the netCDF package → `netcdf/saver` → back to `cf.saver`.
   Whether that resolves depends on which module the interpreter is asked for
   first, and a test suite only ever exercises one order. The failure is an
   `ImportError` naming a name that is obviously there. → **Task 5, Steps 1–2 and
   5**: `test_importing_it_first_works` imports each of five modules first, each in
   its own subprocess.

## 3. Findings that refine the spec

Read these before Task 1. They are what was learned from the code the spec
describes; where one contradicts the spec, this plan follows the finding and
Task 6 records it in the spec's decision log.

**F1 — The saver already speaks `CFDataset` almost everywhere.** PR 2 did more of
this work than the spec's "3000-line diff" risk row implies. Of the forty-odd
places `Saver` touches storage, exactly five still name something netCDF-specific:
the format string in `_ensure_valid_dtype`, the `|S1` char-dimension block in
`_create_generic_cf_array_var`, the ncdata emulated-variable branch in
`_lazy_stream_data`, the `cf_patch` call at the end of `write`, and `__init__`
itself. The rest of the class moves verbatim.

**F2 — The condition is compound, and only half of it is the dataset's business.**
Today's guard reads "int64 or unsigned, *and* one of three classic formats".
`supports_dtype` answers the second half. The first half stays in the generic
saver, because it is not a question about the store: it says which dtypes are
worth narrowing to int32 rather than giving up on. Keeping the split means
`supports_dtype` can answer honestly about dtypes the narrowing branch never sees
— strings on netCDF3, say — without changing what the saver does with them.

```python
is_narrowable_integer = np.issubdtype(values.dtype, np.int64) or np.issubdtype(
    values.dtype, np.unsignedinteger
)
if is_narrowable_integer and not self._dataset.supports_dtype(values.dtype):
```

**F3 — `NETCDF3_64BIT` never reaches the guard, and this pull request must keep it
that way.** netCDF4 reports `file_format` as `"NETCDF3_64BIT_OFFSET"` for a file
created with `netcdf_format="NETCDF3_64BIT"`, and that string is not in the tuple
the saver tests against **[verified: `NetCDFDataset(p, mode="w",
netcdf_format="NETCDF3_64BIT").dataset.file_format`]**. So an int64 cube saved to
that format is never cast down, and the save fails inside the C library:

```
RuntimeError: NetCDF: Not a valid data type or _FillValue type mismatch:
(variable 'small', group '/')
```

**[verified: `iris.save(Cube(np.arange(4, dtype=np.int64)), p,
netcdf_format="NETCDF3_64BIT")`]**. The other three formats behave as the code
reads. Writing `supports_dtype` to answer honestly would turn that crash into a
successful save, which is a behaviour change, and spec §5 says this pull request
makes none. So the netCDF implementation keeps the same three-string list, with a
comment naming the issue, and Task 1 pins the crash in a test so that the next
person to see it knows it was left alone on purpose. Task 6 raises the issue.

**F4 — The generic saver needs `format` only for one error message.** After
`supports_dtype` takes the branch, `self._dataset.dataset.file_format` survives in
exactly one place: the `ValueError` naming the format that refused the cast. Spec
§4.2 says the user still reads `NETCDF3_CLASSIC`, so `CFDataset.format` supplies
it. `CFDatasetVariable.format` is not needed by this plan; PR 4 adds it for the
read side.

**F5 — `_dask_locks` is already generic, and moving it is safe for the import
graph.** It imports `threading` and four `dask` modules, and nothing from Iris
**[verified: `grep -n "^import\|^from" lib/iris/fileformats/netcdf/_dask_locks.py`]**.
`netcdf/_dataset.py` imports it as `from . import _dask_locks` and will import it as
`from iris.fileformats.cf import _dask_locks`. That is the same shape as the
`from iris.fileformats.cf.dataset import CFDataset` already on line 33 of that file,
which works despite `cf/__init__.py` importing `_reader`, which imports
`netcdf/_dataset.py`: the submodule has no import back into the package, so Python
finishes it while the parent package is still partly initialised.

**F6 — Four module constants move and four names need aliases, but they are not the
same four.** Spec §4.8 lists `CFNameCoordMap`, `CF_CONVENTIONS_VERSION`,
`MESH_ELEMENTS` and `SPATIO_TEMPORAL_AXES` as the aliased names. All four are
defined in `netcdf/saver.py` today and re-exported from `netcdf/__init__.py`, which
is where users reach them and so where the alias has to be. `_CF_ATTRS`,
`_CF_DATA_ATTRS`, `_CF_GLOBAL_ATTRS`, `_UKMO_DATA_ATTRS`, `_FACTORY_DEFNS` and
`SaverFillValueWarning` also move, and are private, so they get no alias. One
exception: `iris/cube.py` imports `_CF_GLOBAL_ATTRS` from the saver, so its import
is repointed in Task 5 rather than aliased.

**F7 — Two deferred imports in `cf/loader.py` exist only because of where the saver
lives.** They are commented
`# TODO: make this a plain module-scope import once the saver is relocated`. After
the move, `_CF_ATTRS` comes from `cf/saver.py` and the loader can import it at
module scope. `Saver._DATALESS_ATTRNAME` becomes `CFSaver._DATALESS_ATTRNAME`,
which means the dataless marker must live on the generic class, not the netCDF
subclass. It already describes a CF-level convention rather than a netCDF one.

**F8 — `netcdf/saver.py` imports the netCDF package logger, and `cf/saver.py`
cannot.** `from . import logger` at the top of today's file resolves to
`iris.fileformats.netcdf.logger`, re-exported for the module's users and otherwise
unused. `cf/saver.py` neither needs it nor can have it: `iris.fileformats.cf`
defines no logger. The import stays with `netcdf/saver.py`, where the bare `logger`
statement below it keeps the linter quiet.

**F9 — `write()` has to exist on both classes, with different signatures.** The
generic body is unchanged apart from the keywords it reads. `CFSaver.write` takes
`cube, local_keys=None, unlimited_dimensions=None, **encoding`, bundles nothing,
and passes `encoding` through to `create_variable`. `Saver.write` keeps today's
twelve explicit keywords, bundles the four compression ones exactly as today, and
calls `super().write(...)`. Keeping the explicit keywords is not optional: they are
documented API, they carry defaults users rely on (`complevel=4`, `shuffle=True`),
and `save()` passes them positionally in places.

**F10 — The saver's unit tests stay where they are, and that is not an oversight.**
Every test in `tests/unit/fileformats/netcdf/saver/` drives the generic machinery
by constructing a netCDF `Saver`, because a netCDF file is the only store there
is on this branch. Moving them under `cf/` would leave tests in the CF package
that open netCDF files, which is worse than leaving them. `cf/saver.py` is
therefore covered the way it was covered before it moved: through the only
subclass that exists. PR 6 adds a second one, and that is the point at which a
shared body is worth factoring out, the way `cf/dataset/contract.py` already is.
Say this in the pull request body, because a reviewer will reasonably ask where
the new module's tests are.

**F11 — `netcdf/saver.py` has an import nothing in it uses.** Line 64 is
`import iris.fileformats.cf`, and no other line in the file names it
**[verified: `grep -n "fileformats\.cf"`]**. Ruff does not flag it, because the
name it binds is `iris`, which the file uses constantly. Leave it in
`netcdf/saver.py` when the file splits. It may be load-bearing by preloading the
package for someone else, proving it is not would take more than this pull
request's budget, and deleting it is a change with no upside here.

**F12 — `cf/saver.py` will be about 2400 lines, well over the ~1000-line aim.** So is
the module it comes from, and splitting it is not this pull request's job. The aim
in `lib/iris/AGENTS.md` governs new modules; this one is a relocation of an existing
module whose size is the status quo. Splitting the CF saver into coherent pieces is
worth doing and deserves its own pull request, with its own review, after the Zarr
work has shown where the seams really are. Note it in the pull request body so a
reviewer does not have to raise it.

## 5. The interface, as these tasks leave it

```python
# iris/fileformats/cf/dataset.py
class CFDataset(ABC):
    @property
    @abstractmethod
    def format(self) -> str: ...           # "NETCDF4", "NETCDF3_CLASSIC", ...

    @abstractmethod
    def supports_dtype(self, dtype: np.dtype) -> bool: ...

# iris/fileformats/netcdf/_dataset.py
class NetCDFDataset(CFDataset):
    @property
    def format(self) -> str:               # self._dataset.file_format
    def supports_dtype(self, dtype) -> bool:   # False for i8/unsigned on classic

# iris/fileformats/cf/saver.py
CF_CONVENTIONS_VERSION: str
MESH_ELEMENTS: tuple[str, str, str]
SPATIO_TEMPORAL_AXES: list[str]
class CFNameCoordMap: ...
class SaverFillValueWarning(iris.warnings.IrisSaverFillValueWarning): ...

class CFSaver:

    def _ensure_valid_dtype(self, values, src_name, src_object):
        # Some formats have no 64-bit or unsigned integer types, so we check
        # whether we can store them as int32 instead. Which dtypes are worth
        # narrowing is the saver's question; whether this store holds them is
        # the store's.
        is_narrowable_integer = np.issubdtype(values.dtype, np.int64) or np.issubdtype(
            values.dtype, np.unsignedinteger
        )
        if is_narrowable_integer and not self._dataset.supports_dtype(values.dtype):
            val_min, val_max = (values.min(), values.max())
            if is_lazy_data(values):
                val_min, val_max = _co_realise_lazy_arrays([val_min, val_max])
            # NumPy will inherit values.dtype even if the scalar numbers work
            #  with a smaller type.
            min_dtype = np.promote_types(
                *[np.min_scalar_type(m) for m in (val_min, val_max)]
            )
            # Cast to an integer type the format supports.
            if not np.can_cast(min_dtype, np.int32):
                msg = (
                    "The data type of {} {!r} is not supported by {} and"
                    " its values cannot be safely cast to a supported"
                    " integer type."
                )
                msg = msg.format(src_name, src_object, self._dataset.format)
                raise ValueError(msg)
            values = values.astype(np.int32)
        return values
```

```python
"""Locks that let dask workers co-operate when writing to one target.

A saver writing lazy data hands each chunk to a dask worker, and the workers
must not write over each other. What that takes depends on the dask scheduler,
so this module works out which scheduler is in play and returns a lock to
match. The scheduler must therefore be configured before a lock is asked for.

A dataset implementation asks for one lock per target, identified by its path
or URL, and gives it to every write handle it builds. The netCDF write handle
reopens the file, acquires the lock, writes its chunk, closes the file and
releases the lock, which is the mirror image of what the read path does for a
lazy chunk. A store whose chunks are separate objects needs no such
coordination, and asks for no lock.

For a threaded scheduler the lock is a plain :class:`threading.Lock`. The
workers are threads sharing one address space, so they all hold the same
object, and the identity string is never used.

For a distributed scheduler the lock is a ``distributed.Lock`` named for the
target. It reaches the workers by being serialised along with the task, and
every copy carries the same name, so the scheduler can make them exclude one
another. A worker behaves like a process, and may run on another machine.

The "processes" scheduler is refused by :func:`get_worker_lock`. Supporting it
would need a serialisable shared lock that does not require a distributed
scheduler to function.

Writing to one target from genuinely separate processes is a further step
again. For netCDF it needs libnetcdf built with the parallel access option,
which is uncommon: with an ordinary build, opening a file for writing that is
already open for writing simply raises an access error. Iris does not support
that mode at present.

"""
```

    def _create_string_variable(
        self, cube_or_mesh, cf_name, element, element_dims, data
    ):
        """Create the char variable that will hold this unicode string data.

        netCDF has no unicode type, so string data is stored as bytes over an
        extra trailing dimension whose length is the width of the widest
        value. The name of that dimension is appended to ``element_dims``.

        Parameters
        ----------
        cube_or_mesh : :class:`iris.cube.Cube` or :class:`iris.mesh.MeshXY`
            The Cube or Mesh being saved. Named in the error message.
        cf_name : str
            The name the variable is created with.
        element : :class:`iris.coords._DimensionalMetadata`
            The element being saved. Supplies the ``_Encoding`` attribute.
        element_dims : list of str
            The variable's dimension names, appended to in place.
        data : :class:`numpy.ndarray`
            The string values, used for their dtype.

        Returns
        -------
        :class:`~iris.fileformats.cf.dataset.CFDatasetVariable`

        """
        # NOTE: all we are doing here is to calculate the byte dimension length,
        # based on the dtype and any encoding attribute.
        # The actual char --> byte data *translation* is done by the variable,
        # being a _bytecoding_datasets.EncodedVariable.
        string_dimension_depth = data.dtype.itemsize

        # String content (U) instead of bytes (S).
        # For numpy strings, itemsize is **always** a multiple of 4
        if string_dimension_depth % 4 != 0:
            msg = (
                "Unexpected numpy string 'dtype.itemsize' for element "
                f"{cube_or_mesh.name()!r}: "
                f"'dtype.itemsize = {string_dimension_depth}, expected "
                "a multiple of four (always)."
            )
            raise ValueError(msg)
        nchars = string_dimension_depth // 4

        encoding_attr = element.attributes.get("_Encoding", "ascii")
        # Look this up + return a supported encoding name
        # NB implements defaults and raises a warning if given not recognised.
        encoding = bytecoding_datasets._identify_encoding(
            encoding=encoding_attr, var_name=cf_name, writing=True
        )
        width_fns = bytecoding_datasets._ENCODING_WIDTH_TRANSLATIONS[encoding]
        string_dimension_depth = width_fns.nchars_2_nbytes(nchars)

        string_dimension_name = "string%d" % string_dimension_depth

        # Determine whether to create the string length dimension.
        if string_dimension_name not in self._dataset.dimensions:
            while string_dimension_name in self._dataset.variables:
                # Also avoid collision with variable names.
                # See '_get_dim_names' for reason.
                string_dimension_name = self._increment_name(string_dimension_name)
            self._dataset.create_dimension(
                string_dimension_name, string_dimension_depth
            )

        # Add the string length dimension to the variable dimensions.
        element_dims.append(string_dimension_name)

        # Create the label coordinate variable.
        return self._dataset.create_variable(cf_name, "|S1", element_dims)

    def _backend_write(
        self,
        data: np.typing.ArrayLike,
        cf_var: NetCDFDatasetVariable,
    ) -> bool:
        """Write the data here and now, if this backend handles it itself.

        Returns
        -------
        bool
            Whether the data was written. False leaves the caller to write it
            the ordinary way, directly or by a delayed store.

        """
        if cf_var.is_emulated:
            # The variable is not an actual file variable, but an emulating
            # object with an attached data array (either numpy or dask), which should
            # be copied immediately to the target.  This is used as a hook to translate
            # data to/from netcdf data container objects in other packages, such as
            # xarray.
            # See https://github.com/SciTools/iris/issues/4994 "Xarray bridge".
            if cf_var.dtype.kind == "U":
                # We also need to perform string-to-bytes encoding since, in ncdata,
                #  the emulating objects don't do this, and also don't support a
                #  'set_auto_chartostring(True)'.
                # Therefore, do here what an EncodedVariable.__setitem__ would do : ..
                #  .. get details from the file (char) variable to be written ..
                encoder = VariableEncoder.from_var(cf_var.unencoded_variable)
                #  .. apply encoding to get the bytes to write.
                data = encoder.encode_strings_as_bytearray(data)

            # NCZarr cannot be reopened for deferred writes.
            # Collect here; da.store() will be called in __exit__.
            self._nczarr_writes.append((data, cf_var))
            return True

class CFSaver:
    """A manager for saving cubes to a CF-conforming store."""

    def __init__(self, dataset, compute=True, *, owns_dataset=True):
        """Manage saving cubes into an open store.

        Parameters
        ----------
        dataset : :class:`~iris.fileformats.cf.dataset.CFDataset`
            An open, writable store. A subclass opens it and passes it here.
        compute : bool, default=True
            If ``True``, delayed variable saves will be completed on exit from
            the saver context, after the store is closed, equivalent to
            :meth:`complete`.

            If ``False``, the store is created and closed without writing the
            data of variables whose source data was lazy. Those writes can be
            completed later, see :meth:`delayed_completion`.
        owns_dataset : bool, default=True
            Whether leaving the context should close the store. ``False`` when
            the caller supplied an already-open store and will close it itself.

        """
        # All persistent variables
        #: CF name mapping with iris coordinates
        self._name_coord_map = CFNameCoordMap()
        #: Map of dimensions to characteristic coordinates with which they are identified
        self._dim_names_and_coords = CFNameCoordMap()
        #: List of grid mappings added to the file
        self._coord_systems = []
        #: A dictionary, listing dimension names and corresponding length
        self._existing_dim = {}
        #: A map from meshes to their actual file dimensions (names).
        # NB: might not match those of the mesh, if they were 'incremented'.
        self._mesh_dims = {}
        #: A dictionary, mapping formula terms to owner cf variable name
        self._formula_terms_cache = {}
        #: Whether to complete delayed saves on exit.
        self.compute = compute
        # A list of delayed writes for lazy saving
        # a list of couples (source, target).
        self._delayed_writes = []

        self._dataset = dataset
        self._owns_dataset = owns_dataset
        #: Target filepath
        self.filepath = dataset.location

class Saver(CFSaver):
    """A manager for saving NetCDF/NcZarr files."""

    def __init__(self, filename, netcdf_format, compute=True):
        """<unchanged: today's docstring, including the doctest>"""
        if netcdf_format not in [
            "NETCDF4",
            "NETCDF4_CLASSIC",
            "NETCDF3_CLASSIC",
            "NETCDF3_64BIT",
        ]:
            raise ValueError("Unknown netCDF file format, got %r" % netcdf_format)

        #: Whether the save target is an NCZarr URL.
        self._is_nczarr = False
        # A list of pre-close writes for NCZarr lazy saving.
        # NCZarr cannot be reopened for deferred writes, so lazy data is
        # written before __exit__ closes the file.
        self._nczarr_writes = []

        # Detect if we were passed a pre-opened dataset (or something like one)
        self._to_open_dataset = hasattr(filename, "createVariable")
        if self._to_open_dataset:
            # We were passed a *dataset*, so we don't open (or close) one of our own.
            if compute:
                msg = (
                    "Cannot save to a user-provided dataset with 'compute=True'. "
                    "Please use 'compute=False' and complete delayed saving in the "
                    "calling code after the file is closed."
                )
                raise ValueError(msg)

            # from_existing() handles the thread-safety wrapping.
            dataset = NetCDFDataset.from_existing(filename)

            # In this case the dataset gives a filepath, not the other way around.
            filepath = dataset.location

        else:
            # Given a filepath string/path : create a dataset from that
            try:
                # Lazy import to avoid circular import overhead at module import-time.
                from iris.io import _is_nczarr_fragment

                self._is_nczarr = _is_nczarr_fragment(
                    urlsplit(str(filename)).fragment or None
                )
                if self._is_nczarr:
                    # NCZarr URLs contain a #mode= fragment; Path() strips it.
                    # Keep as a plain string and pass directly to the dataset.
                    filepath = str(filename)
                else:
                    filepath = Path(filename).absolute()
                dataset = NetCDFDataset(
                    filepath, mode="w", netcdf_format=netcdf_format
                )
            except RuntimeError:
                if self._is_nczarr:
                    raise
                dir_name = Path(filepath).parent
                if not dir_name.is_dir():
                    msg = "No such file or directory: {}".format(dir_name)
                    raise IOError(msg)
                if not os.access(dir_name, os.R_OK | os.W_OK):
                    msg = "Permission denied: {}".format(filepath)
                    raise IOError(msg)
                else:
                    raise

        super().__init__(
            dataset, compute=compute, owns_dataset=not self._to_open_dataset
        )

        #: Target filepath. A Path for a local file, which is public API:
        #: the base class has only the dataset's string form of it.
        self.filepath = filepath

        # One lock for the whole file, shared with every variable of it.
        #: A per-file write lock to prevent dask attempting overlapping writes.
        # N.B. the file-write-lock *type* actually depends on the dask scheduler type.
        self.file_write_lock = dataset.write_lock
