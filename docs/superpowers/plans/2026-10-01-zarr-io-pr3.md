**Goal:** Move the format-agnostic half of the netCDF loader into `iris.fileformats.cf.loader`, leaving `iris.fileformats.netcdf.loader` holding only netCDF's entry point and warn-on-use aliases, so that PR 4 can add Zarr loading by implementing one method.

**Architecture:** Today `netcdf/loader.py` mixes three jobs: driving the CF rules engine (generic), deciding chunking policy (generic), and building netCDF data proxies (netCDF-only). This plan separates them along one seam — a new abstract `CFDatasetVariable.read_data()` — then physically moves the generic side to `cf/loader.py` with `git mv`, so the diff reads as a move rather than a rewrite. The netCDF-only body lands on `NetCDFDatasetVariable.read_data()` next to the rest of the netCDF storage adapter. `iris._lazy_data.as_lazy_data` stops recognising `NetCDFDataProxy` by type and takes a caller-supplied `cache_key=` instead, which is what lets the two modules stop importing each other.

**Tech Stack:** Python 3.12–3.14, NumPy, Dask, netCDF4 (via `iris.fileformats.netcdf._thread_safe_nc`), pytest + pytest-mock, pre-commit (ruff, numpydoc, mypy, sort-all, and the repository's local hooks), Sphinx.

## Review Focus

Five things the spec implies, that no existing test exercises, and that would bite
a real user. Each is pinned by a test in the task named.

1. **A name that users *assign to* silently stops working.** A module-level
   `__getattr__` forwards reads but cannot see writes — PEP 562 defines no
   `__setattr__` hook — so forwarding `DEBUG` would leave
   `iris.fileformats.netcdf.loader.DEBUG = True` succeeding and doing nothing.
   `_LAZYVAR_MIN_BYTES` has the same shape and eight call sites, three of which
   assign. → **Task 3, Steps 1–2 and 9**: `test_debug_is_not_relocated` pins
   that `DEBUG` keeps a real attribute here and is absent from
   `_RELOCATED_NAMES`, and `test_assignment_to_a_relocated_name_does_not_reach_the_new_home`
   writes the forward's limitation down. Task 3 Step 11 repoints every
   `_LAZYVAR_MIN_BYTES` site rather than aliasing it.
2. **The dask array cache silently stops working.** A cache miss costs only time,
   so an omitted or altered `cache_key=` would pass every existing test while
   making every multi-cube file load slower. → **Task 1, Steps 1–4 and 7–9**:
   `test_key_is_the_caller_s_string` asserts the exact key tuple,
   `test_second_call_reuses_the_cached_array` asserts a second call does not
   rebuild, and Step 7's test asserts the netCDF loader still supplies
   `repr(proxy)`.
3. **A CF attribute leaks onto the cube.** `read_data` reads `_FillValue`,
   `scale_factor` and `add_offset` from the storage object's *untracked*
   attributes, where today they are read from the `CFVariable`'s *tracked* copy.
   An untracked read that was previously tracked would let a CF-reserved attribute
   survive onto `cube.attributes`. → **Task 2, Steps 15–16**:
   `test_reading_data_changes_no_attribute_tracking` compares the names
   `cf_attrs_unused()` returns before and after a `_get_cf_var_data()` call, for
   a variable carrying all four reserved names.
4. **`CHUNK_CONTROL.from_file()` starts rejecting small cubes.** The `KeyError`
   for an unchunked data variable sits *after* the "small enough to read whole"
   shortcut. Hoisting the check into the CF layer, which is where the
   "is this the data variable" fact lives, would make a small contiguous cube
   raise where today it loads. → **Task 2, Steps 17–18**:
   `test_from_file_still_loads_a_small_unchunked_cube` loads a sub-5000-byte
   unchunked cube inside `from_file()`, with the module's threshold-zeroing
   fixture put back for the duration.
5. **ncdata's emulated variables and VLEN variables lose their special handling.**
   Emulated datasets (issue #4994) and netCDF `VLType` variables each take an early
   exit that never builds a proxy; both are exercised only indirectly today. →
   **Task 2, Steps 11–14**: `test_emulated_array_is_returned_as_it_stands` and
   `test_emulated_array_builds_no_proxy` cover emulation, and
   `test_vltype_warns_that_the_size_is_unknown` covers the VLEN warning that
   today's `_vl_hint` tests never assert.

[#7303](https://github.com/SciTools/iris/pull/7303) is **squash-merged** into

Record this SHA now; it is the fence between PR 2's history and PR 3's:

```

```

After #7303 is merged, and **only** then:


Check it worked before opening the PR:

```bash

git diff --stat upstream/brownfield...zarr-io-pr-3     # PR 3's files only
```

If the rebase does conflict, the cause is upstream work landing on `brownfield`
between #7303 and the rebase, not PR 2 itself. Resolve normally.

If PR 3 is already open at this point, finish by editing its description to
delete the blockquote warning that #7303's commits are showing through. It has
just stopped being true, and a stale warning sends reviewers looking for a
problem that is no longer there.

Do **not** merge `brownfield` into `zarr-io-pr-3` instead. A merge keeps PR 2's
72 commits reachable from the branch tip, which is the thing this avoids.

Until then, develop on `zarr-io-pr-3` as it stands.

**Do not wait for #7303 to open PR 3.** Its human reviewers are the constraint,
and the expectation is that PR 3 will be opened, and probably reviewed, while
#7303 is still outstanding. So the realistic order is: build all six tasks, open
the pull request, and rebase whenever #7303 eventually lands. Task 6 Step 1 says
the same thing from the other end.

The cost of opening first is cosmetic but startling, and the PR body warns about
it: until the rebase happens, GitHub computes PR 3's diff against `brownfield`
and therefore shows all 72 of PR 2's commits inside PR 3. Nothing is wrong, and
the rebase removes them in one step. Reviewers should read PR 3's own commits —
the ones after `26c4a73c8` — and nothing earlier.

## 3. Findings that refine the spec

Read these before Task 1. They are what was learned from the code the spec
describes; where one contradicts the spec, this plan follows the finding and
Task 5 records it in the spec's decision log.

**F1 — The import `_lazy_data` sheds is one module deeper than the spec says.**
Spec §5 says PR 3 removes `iris/_lazy_data.py`'s "import of
`iris.fileformats.netcdf`". The actual statement, deferred inside `as_lazy_data`
at `lib/iris/_lazy_data.py:302`, is
`from iris.fileformats.netcdf._thread_safe_nc import NetCDFDataProxy`. Removing
it has exactly the effect the spec wants: after Task 1, `iris._lazy_data` imports
nothing from `iris.fileformats`.

**F2 — There are two proxy classes, and today's `isinstance` catches both.**
`EncodedNetCDFDataProxy` (`netcdf/_bytecoding_datasets.py:462`) subclasses
`_thread_safe_nc.NetCDFDataProxy`. The loader picks between them per variable.
Both paths must pass `cache_key=`, or byte-decoded variables silently stop being
cached.

**F3 — The cache key is built from the *normalised* chunks.** In today's
`as_lazy_data`, `key = (repr(data), chunks, asarray, meta.dtype, type(meta))` is
computed *after* `chunks` has been through `_optimum_chunksize`. `cache_key=` must
be consumed at that same point, not at the top of the function, or the keys change.

**F4 — `_get_cf_var_data` is half generic and half netCDF, and the netCDF half
has three early exits.** Generic: the 5000-byte threshold, `_get_actual_dtype`,
and the chunk-control block. netCDF-only: the emulated-dataset shortcut, VLEN
sizing and its warning, the `_thread_safe_nc.default_fillvals` default, and the
proxy-class choice. The seam is one new abstract method, `read_data()`, agreed
with the user on 2026-10-01 in preference to three narrower hooks.

**F5 — `read_data` needs one CF-layer fact, at a point only the backend reaches.**
The chunk-control block raises `KeyError` for an unchunked variable under
`from_file()` *only* when the variable is a `CFDataVariable`, and only *after*
the emulated and small-array early exits have been passed. The dataset variable
cannot know whether it is a cube's phenomenon variable, and the check cannot be
hoisted without changing behaviour (Review Focus 4). So `read_data` takes a
single zero-argument callable, `chunking_policy`, that it invokes only once it
has decided the result will be lazy. `cf/loader._get_cf_var_data` binds it with
`partial(_chunks_from_chunk_control, cf_var)`.

**F6 — `netcdf/_dataset.py` cannot import `cf.loader` at module level.**
`cf/__init__.py` imports `cf/_reader.py`, which imports
`iris.fileformats.netcdf._dataset`. A module-level import back would leave
`netcdf._dataset` partially initialised. Use a function-level import inside
`read_data`, and import the **module**, not its members:
`from iris.fileformats.cf import loader as cf_loader`. Member imports would
freeze `_LAZYVAR_MIN_BYTES` at call time and break the eight tests that patch it.

**F7 — `DEBUG` stays put, and the moved code reaches back for it.** Spec §4.8
lists `netcdf.DEBUG` among the names that do not move, but its only reader —
`if DEBUG:` in `_load_cube_inner`, a single line — is generic code that does
move. The obvious resolution, making `cf.loader.DEBUG` the live flag and
leaving a warn-on-use forward behind, does not work: `DEBUG` is a bool, so the
*only* way anyone uses it is to rebind it, and PEP 562 gives a module a
`__getattr__` and no `__setattr__`. `iris.fileformats.netcdf.loader.DEBUG = True`
would succeed and change nothing. Two test modules already depend on that
assignment working — `nc_load_rules/actions/__init__.py` patches the name at
lines 82 and 85. Replacing the module's `__class__` to intercept the write is
the sort of cleverness `lib/iris/AGENTS.md` rules out.

So `DEBUG` keeps its definition in `netcdf/loader.py`, and `_load_cube_inner`
reads it through a deferred `from iris.fileformats.netcdf import loader as
netcdf_loader`, by module attribute rather than by value, so that assignment
and `mocker.patch` both still bite. `netcdf/__init__.py` needs no change: its
eager `from .loader import DEBUG, NetCDFDataProxy, load_cubes` is still a
plain import of three names that are still there, which is also what keeps
spec §4.8's "warnings on use, not on import" true. Only `CHUNK_CONTROL` and
`ChunkControl` go through `__getattr__`; they are objects, used through their
context managers, never rebound.

The direction of the resulting dependency is the opposite of this PR's: a CF
module reaching into a netCDF one for a debug flag. It is one line, behind a
deferred import, and PR 4's Zarr loader will honour the same flag — which is
odd but harmless, and better than a flag that silently ignores being set.

**F8 — Two imports have to point backwards from `cf` to `netcdf` until PR 5.**
`_add_unused_attributes` uses `_CF_ATTRS` and `_load_cube_inner` uses
`Saver._DATALESS_ATTRNAME`, both from `netcdf/saver.py`. In `cf/loader.py` these
must be **function-level** imports: a module-level one risks a partially
initialised `iris.fileformats.netcdf` whenever `netcdf/__init__.py` is the entry
point. Each gets a comment naming spec §4.1, which moves the saver to
`cf/saver.py` and dissolves both.

**F9 — Moving the attribute reads off the tracked copy is safe, and has to be
shown to be.** Today `_get_cf_var_data` reads `_FillValue`, `scale_factor` and
`add_offset` through `cf_var.attributes`, a `TrackedAttributes`. After the move
`read_data` reads them through `NetCDFDatasetVariable.attributes`, which tracks
nothing. This is behaviour-preserving because all four of `_FillValue`,
`add_offset`, `missing_value` and `scale_factor` appear both in
`_variables._CF_ATTRS_IGNORE` — so `TrackedAttributes` pre-seeds them as already
read — and in `saver._CF_ATTRS`, which `_add_unused_attributes` filters out
regardless. Two independent reasons, neither obvious; hence Review Focus 3.

**F10 — `cf_var.filename` and `variable.location` are the same string, with one
fallback that no longer applies.** `CFVariable.__init__` sets
`self.filename = data.location`, falling back to `"<unknown_filename>"` if that
raises `AttributeError`. `location` is abstract on `CFDatasetVariable`, so for a
real dataset it always exists. Mock-based tests must give their fake variable a
`location`.

**F11 — Collapsing the two `as_lazy_data` calls into one is identical.** The
`AS_DASK` branch calls `as_lazy_data(proxy, meta=..., chunks="auto")` with no
`dims_fixed`; the other calls it with `dims_fixed=tuple(...)`. Expressing
`AS_DASK` as the pair `("auto", None)` and using a single call site is
byte-identical, because `dims_fixed=None` is the parameter's default.

**F12 — The two size constants part company.** `_MEAN_VL_ARRAY_LEN` exists for
netCDF `VLType` variables and travels with `read_data` into
`netcdf/_dataset.py`. `_LAZYVAR_MIN_BYTES` is generic policy and stays in
`cf/loader.py`, read as `cf_loader._LAZYVAR_MIN_BYTES` so it remains patchable.

**F13 — Task 1 must come first, for an import reason.** `netcdf/_dataset.py`
needs `from iris._lazy_data import as_lazy_data` at module level, so that
`test__chunk_control` can patch `iris.fileformats.netcdf._dataset.as_lazy_data`.
That import is only safe once Task 1 has removed `_lazy_data`'s import of
`netcdf._thread_safe_nc`.

**F14 — Sphinx will not break, and will not need a new file.** API pages come
from `sphinxcontrib.apidoc` (`docs/src/conf.py:279-292`), so
`iris.fileformats.cf.loader` gets a page with no RST written by hand;
`docs/src/generated/` is gitignored. `nitpicky` is not set in `conf.py`, so the
two historical whatsnew cross-references to
`iris.fileformats.netcdf.loader.CHUNK_CONTROL` degrade to plain text rather than
failing the `-W` build.

**F15 — The references to repoint are these, and no others.** Established by
`grep -rn` over `lib/`, `docs/` and `benchmarks/` for every top-level name in
`netcdf/loader.py`.

*Library:* `_nc_load_rules/helpers.py:40` (the import; its call sites at 606,
1578, 1583, 1691 and 1767 need no change); `netcdf/ugrid_load.py:213,218,270,275,437`;
`netcdf/_dataset.py` (the deferred import Task 2 adds); `cf/_variables.py:124`,
`_nc_load_rules/actions.py:655` and `_nc_load_rules/engine.py:18` — three prose
cross-references.

*Tests, for `_LAZYVAR_MIN_BYTES`:* `integration/test_cube.py:23`,

`integration/netcdf/test_stringdata.py:33,34,36,406`,

```python
def _chunks_from_chunk_control(cf_var):
    """Return the ``(chunks, dims_fixed)`` pair for a lazy array of this variable.

    This is the one piece of a lazy array that is CF's business rather than the
    storage's: how big the dask chunks should be, given the store's own chunking
    and whatever :data:`CHUNK_CONTROL` context is active.

    Parameters
    ----------
    cf_var : :class:`iris.fileformats.cf.CFVariable`
        The variable the array is being built for.

    Returns
    -------
    tuple
        ``("auto", None)`` in :attr:`ChunkControl.Modes.AS_DASK`, otherwise a
        list of chunk sizes and a tuple of per-dimension "fixed" flags, both
        shaped for :func:`iris._lazy_data.as_lazy_data`.

    Raises
    ------
    KeyError
        In :attr:`ChunkControl.Modes.FROM_FILE`, when ``cf_var`` is a cube's
        data variable and the store offers no chunking to adopt.

    """
    if CHUNK_CONTROL.mode is ChunkControl.Modes.AS_DASK:
        return "auto", None

    # Get the chunking specified for the variable : this is either a shape, or
    # None if the variable is unchunked.
    chunks = cf_var.cf_data.chunking
    if chunks is None:
        # Unchunked : either a non-version-4 file, or a contiguous
        # version-4 variable. Neither offers a chunking to adopt.
        if CHUNK_CONTROL.mode is ChunkControl.Modes.FROM_FILE and isinstance(
            cf_var, iris.fileformats.cf.CFDataVariable
        ):
            raise KeyError(
                f"{cf_var.cf_name} does not contain pre-existing chunk specifications."
                f" Instead, you might wish to use CHUNK_CONTROL.set(), or just use default"
                f" behaviour outside of a context manager. "
            )
        # Equivalent to chunks=None, but value required by chunking control
        chunks = list(cf_var.shape)
    else:
        # The chunk-control block below assigns into this.
        chunks = list(chunks)

    # Modify the chunking in the context of an active chunking control.
    # N.B. settings specific to this named var override global ('*') ones.
    dim_chunks = CHUNK_CONTROL.var_dim_chunksizes.get(
        cf_var.cf_name
    ) or CHUNK_CONTROL.var_dim_chunksizes.get("*")
    dims = cf_var.dimensions
    if CHUNK_CONTROL.mode is ChunkControl.Modes.FROM_FILE:
        dims_fixed = np.ones(len(dims), dtype=bool)
    elif not dim_chunks:
        dims_fixed = None
    else:
        # Modify the chunks argument, and pass in a list of 'fixed' dims, for
        # any of our dims which are controlled.
        dims_fixed = np.zeros(len(dims), dtype=bool)
        for i_dim, dim_name in enumerate(dims):
            dim_chunksize = dim_chunks.get(dim_name)
            if dim_chunksize:
                if dim_chunksize == -1:
                    chunks[i_dim] = cf_var.shape[i_dim]
                else:
                    chunks[i_dim] = dim_chunksize
                dims_fixed[i_dim] = True
    if dims_fixed is None:
        dims_fixed = [dims_fixed]
    return chunks, tuple(dims_fixed)
```

```python
        # module-level import would be a cycle; and the tests patch
        # _LAZYVAR_MIN_BYTES on the module object.
        from iris.fileformats.netcdf import loader

        if self.is_emulated:
            # The variable is not an actual netCDF4 file variable, but an
            # emulating object with an attached data array (either numpy or
            # dask), which can be returned immediately as-is. This is the hook
            # ncdata (https://github.com/SciTools/ncdata) uses to translate data
            # to and from other packages' netCDF data containers.
            # See https://github.com/SciTools/iris/issues/4994.
            result = self.emulated_data_array
            if result.dtype.kind == "S":
                # We must also perform any byte-to-string decoding since, in
                #  ncdata, the emulating objects don't do this, and also don't
                #  support a 'set_auto_chartostring(True)'.
                #  Therefore, do here what an EncodedVariable.__getitem__ would
                #  do : ..
                # .. get details based on the file (type 'char') variable  ..
                encoder = _bytecoding_datasets.VariableEncoder.from_var(
                    self.unencoded_variable
                )
                # .. convert byte array to strings.
                result = encoder.decode_bytes_to_stringarray(result)
            return result

        # Determine size of data; however can't do this for variable length (VLEN)
        # netCDF arrays as the size of the array can only be known by reading the
        # data; see https://github.com/Unidata/netcdf-c/issues/1893.
        # Note: "Variable length" netCDF types have a datatype of `nc.VLType`.
        if self.is_variable_length:
            msg = (
                f"NetCDF variable `{self.name}` is a variable length type of kind "
                f"{self.dtype} "
                "thus the total data size cannot be known in advance. This may affect "
                "the lazy loading of the data."
            )
            warnings.warn(msg, category=iris.warnings.IrisLoadWarning)

            # Give user the chance to pass a hint of the average variable length array
            # size via the chunk control context manager. This allows for better
            # decisions to be made on whether the data should be lazy-loaded or not.
            mean_vl_array_len = _MEAN_VL_ARRAY_LEN
            chunk_control = loader.CHUNK_CONTROL
            if chunk_control.mode is not chunk_control.Modes.AS_DASK:
                if chunks := chunk_control.var_dim_chunksizes.get(self.name):
                    if vl_chunk_hint := chunks.get("_vl_hint"):
                        mean_vl_array_len = vl_chunk_hint

            # Special handling for strings (`str` type) as these don't have an
            # itemsize attribute; assume 4 bytes which is sufficient for unicode
            # character storage
            itemsize = 4 if self.dtype is str else self.dtype.itemsize

            # For `VLType` self.size will just return the known dimension size.
            total_bytes = self.size * mean_vl_array_len * itemsize
        else:
            # Normal NCVariable type:
            total_bytes = self.size * self.dtype.itemsize

        if total_bytes < loader._LAZYVAR_MIN_BYTES:
            # Don't make a lazy array, as it will cost more memory AND more time
            # to access.
            result = self[:]

            # Special handling of masked scalar value; this will be returned as
            # an `np.ma.masked` instance which will lose the original dtype.
            # Workaround for this it return a 1-element masked array of the
            # correct dtype. Note: this is not an issue for masked arrays,
            # only masked scalar values.
            if result is np.ma.masked:
                result = np.ma.masked_all(1, dtype=self.dtype)
            return result

        # Get lazy chunked data out of a cf variable.
        # Creates Dask wrappers around data arrays for any cube components which
        # can have lazy values, e.g. Cube, Coord, CellMeasure, AuxiliaryVariable.
        dtype = loader._get_actual_dtype(self)

        # Make a data-proxy that mimics array access and can fetch from the file.
        # Note: Special handling needed for "variable length string" types which
        # return a dtype of `str`, rather than a numpy type; use `S1` in this case.
        if getattr(self.dtype, "kind", None) == "U":
            # Special handling for "string variables".
            fill_value = ""
        else:
            fill_dtype = "S1" if self.dtype is str else self.dtype.str[1:]
            fill_value = self.attributes.get(
                "_FillValue", _thread_safe_nc.default_fillvals[fill_dtype]
            )

        # Switch type of proxy, based on type of variable.
        # It is done this way, instead of using an instance variable, because the
        #  limited nature of the wrappers makes a stateful choice awkward,
        #  e.g. especially, "variable.group()" is *not* the parent DatasetWrapper.
        if isinstance(self.variable, _bytecoding_datasets.EncodedVariable):
            proxy_class = _bytecoding_datasets.EncodedNetCDFDataProxy
        else:
            proxy_class = _thread_safe_nc.NetCDFDataProxy

        proxy = proxy_class(self.variable, dtype, self.location, fill_value)

        chunks, dims_fixed = chunking_policy()
        return as_lazy_data(
            proxy,
            meta=proxy.dask_meta,
            chunks=chunks,
            dims_fixed=dims_fixed,
            cache_key=repr(proxy),
        )
```

**What goes where, and why**

Three names decide the shape of this task.

`CHUNK_CONTROL` and `ChunkControl` are in the spec's relocation table
(§4.8): they move to `iris.fileformats.cf.loader`, and the old names keep
working for one deprecation cycle, warning on use.

`DEBUG` is in the spec's *other* list — the names that explicitly do **not**
move, because they are netCDF API (§4.8: "``netcdf.save``, ``netcdf.Saver``,
``netcdf.load_cubes``, ``netcdf.save_mesh``, ``netcdf.NetCDFDataProxy``,
``netcdf.DEBUG``"). Its one reader, `_load_cube_inner`, is generic code that
is moving. So `DEBUG` stays defined where it is and the moved code reaches
back for it, rather than the reverse. That is the right way round for a
second reason: `DEBUG` is a flag users set by assignment, and a module
`__getattr__` forward cannot intercept assignment (PEP 562 defines
`__getattr__` for modules and nothing for `__setattr__`). A name that is only
ever read can be forwarded; a name that is written cannot. `DEBUG` is
written, so it does not get forwarded.

`load_cubes` stays too, for the same reason: opening a list of file sources
is netCDF's job, and `iris.fileformats.netcdf.load_cubes` is in the
do-not-move list. It imports the four CF-layer functions it drives.

Two files that might look like they need editing do not. `cf/__init__.py`
re-exports the public names `iris.fileformats.cf` exports *today*, and
`CHUNK_CONTROL` is not one of them: the spec's relocation table (§4.8) names
`iris.fileformats.cf.loader.CHUNK_CONTROL`, with the submodule spelled out, so
do not add it to `cf/__init__.py` or to its `__all__`. `netcdf/__init__.py`
imports `DEBUG`, `NetCDFDataProxy` and `load_cubes` from `.loader` (line 34)
and lists all three in `__all__` — all three stay, so that line is already
correct and must not be touched.

```python
"""Unit tests for the deprecated aliases left behind in the netCDF loader.

``CHUNK_CONTROL`` and ``ChunkControl`` moved to
:mod:`iris.fileformats.cf.loader`; the old names still answer, with a warning.
"""

import importlib
import warnings

import pytest

from iris._deprecation import IrisDeprecation
from iris.fileformats.cf import loader as cf_loader
from iris.fileformats.netcdf import loader as netcdf_loader

RELOCATED = ["CHUNK_CONTROL", "ChunkControl"]


@pytest.mark.parametrize("name", RELOCATED)
def test_the_old_name_warns(name):
    with pytest.warns(IrisDeprecation, match=f"netcdf.loader.{name}"):
        getattr(netcdf_loader, name)


@pytest.mark.parametrize("name", RELOCATED)
def test_the_message_names_the_new_location(name):
    with pytest.warns(IrisDeprecation, match=r"iris\.fileformats\.cf\.loader"):
        getattr(netcdf_loader, name)


@pytest.mark.parametrize("name", RELOCATED)
def test_the_alias_is_the_same_object(name):
    # Spec 4.8: "The alias is the same object, not a copy, so existing code
    # keeps working including inside a with CHUNK_CONTROL.set(...)". A copy
    # would give a with-block that silently chunked nothing.
    with pytest.warns(IrisDeprecation):
        assert getattr(netcdf_loader, name) is getattr(cf_loader, name)


def test_importing_the_module_does_not_warn():
    # Spec 4.8: "Warnings are emitted on use, not on import, so simply
    # importing iris.fileformats.netcdf stays quiet."
    with warnings.catch_warnings():
        warnings.simplefilter("error")
        importlib.reload(importlib.import_module("iris.fileformats.netcdf"))


def test_an_unrelated_name_raises_without_warning():
    # hasattr() probes land in __getattr__ too, and a probe that comes back
    # False is not a use of anything.
    with warnings.catch_warnings():
        warnings.simplefilter("error")
        with pytest.raises(AttributeError, match="no_such_name"):
            netcdf_loader.no_such_name


def test_debug_is_not_relocated():
    # Spec 4.8 lists netcdf.DEBUG among the names that do not move. It is a
    # flag users assign to, and a module __getattr__ cannot intercept
    # assignment - so forwarding it would make `netcdf.loader.DEBUG = True`
    # silently stop working. Pin that it is a real attribute here.
    with warnings.catch_warnings():
        warnings.simplefilter("error")
        assert netcdf_loader.DEBUG is False
    assert "DEBUG" not in netcdf_loader._RELOCATED_NAMES


def test_assignment_to_a_relocated_name_does_not_reach_the_new_home():
    # The known limitation of the PEP 562 forward, written down so that it is
    # a documented edge and not a surprise. Assigning here shadows the
    # forward; it does not change iris.fileformats.cf.loader. Nothing in Iris
    # assigns to CHUNK_CONTROL - it is used through its context managers - but
    # if that ever changes, this test says where to look.
    original = cf_loader.CHUNK_CONTROL
    netcdf_loader.CHUNK_CONTROL = "shadow"
    try:
        assert netcdf_loader.CHUNK_CONTROL == "shadow"
        assert cf_loader.CHUNK_CONTROL is original
    finally:
        del netcdf_loader.CHUNK_CONTROL
```

```python
# Copyright Iris contributors
#
# This file is part of Iris and is released under the BSD license.
# See LICENSE in the root of the repository for full licensing details.
"""Load Iris cubes from NetCDF files and OPeNDAP URLs.

.. z_reference:: iris.fileformats.netcdf.loader
   :tags: topic_load_save

   API reference

What is left here is what is genuinely netCDF's: opening the file sources, and
the proxy class that reads from them. Interpreting what is inside is
:mod:`iris.fileformats.cf.loader`'s job.

.. deprecated:: 3.17
    ``CHUNK_CONTROL`` and ``ChunkControl`` have moved to
    :mod:`iris.fileformats.cf.loader`, because chunking policy is not specific
    to netCDF. They can still be reached here, with a warning, for one
    deprecation cycle.

See : `NetCDF User's Guide <https://docs.unidata.ucar.edu/nug/current/>`_
and `netCDF4 python module <https://github.com/Unidata/netcdf4-python>`_.

Also : `CF Conventions <https://cfconventions.org/>`_.

"""

from collections.abc import Iterable
from functools import partial
import warnings

from iris._deprecation import warn_deprecated
from iris.fileformats.cf.loader import (
    _actions_engine,
    _load_aux_factory,
    _load_cube,
    _translate_constraints_to_var_callback,
)
import iris.warnings

# Show actions activation statistics.
# NOTE: read by iris.fileformats.cf.loader._load_cube_inner, through this
# module rather than by value, so that assigning to it here still works.
DEBUG = False

# Get the logger : shared logger for all in 'iris.fileformats.netcdf'.
from . import _bytecoding_datasets, logger

# An expected part of the public loader API, but includes thread safety
#  concerns so is housed in _thread_safe_nc.
# NOTE: this is the *default*, as required for public legacy api
#  - in practice, when creating our proxies we dynamically choose between this and
#    :class:`_thread_safe_nc.DatasetWrapper`, depending on
#    :data:`_bytecoding_datasets.DECODE_TO_STRINGS_ON_READ`
NetCDFDataProxy = _bytecoding_datasets.EncodedNetCDFDataProxy

#: Names that moved to :mod:`iris.fileformats.cf.loader` in Iris 3.17 and are
#: still readable here, with a warning, for one deprecation cycle.
#:
#: Read-only: a module ``__getattr__`` cannot intercept assignment, so a name
#: that users *set* must keep its definition here instead. ``DEBUG`` is the
#: one such name, and is deliberately absent from this set.
_RELOCATED_NAMES = frozenset({"CHUNK_CONTROL", "ChunkControl"})


def __getattr__(name):
    """Forward a relocated name to :mod:`iris.fileformats.cf.loader`.

    Parameters
    ----------
    name : str
        The attribute being looked up. Python calls this only for names that
        are not already module attributes.

    Returns
    -------
    Any
        The object of that name in :mod:`iris.fileformats.cf.loader` - the
        same object, not a copy.

    Raises
    ------
    AttributeError
        If ``name`` is not one of the relocated names. Raised without warning,
        so that a ``hasattr`` probe that comes back False stays quiet.

    """
    if name not in _RELOCATED_NAMES:
        raise AttributeError(f"module {__name__!r} has no attribute {name!r}")

    # Deferred so that importing this module stays quiet and cheap.
    from iris.fileformats.cf import loader as cf_loader

    warn_deprecated(
        f"iris.fileformats.netcdf.loader.{name} has moved to "
        f"iris.fileformats.cf.loader.{name}, because it is not specific to "
        "netCDF. The name here will be removed in a future release."
    )
    return getattr(cf_loader, name)
```

````markdown
## What this does

`iris/fileformats/netcdf/loader.py` did three jobs. Two of them —
driving the CF rules engine, and deciding dask chunk sizes — are not
netCDF's. They only lived there because netCDF was the only format that
did them.

This moves those two to a new `iris.fileformats.cf.loader`, with
`git mv`, so the history follows the code. What stays at the old path is
what is genuinely netCDF's: `load_cubes`, `NetCDFDataProxy` and `DEBUG`.

Reading a variable's array is the one place where the format does show
through. That becomes a single abstract method on the storage interface
#7303 introduced:

```python
class CFDatasetVariable(ABC):
    @abstractmethod
    def read_data(self, chunking_policy): ...
```

The CF loader supplies `chunking_policy` — a zero-argument callable that
answers "what chunks, if this comes back lazy" — and the netCDF
implementation decides everything else. That is the seam the Zarr loader
plugs into in the next pull request; there is nothing else for it to
implement.

One supporting change made this possible. `iris._lazy_data.as_lazy_data`
used to recognise `NetCDFDataProxy` by `isinstance` to decide whether a
result was cacheable, which meant the bottom of the lazy-data stack
imported a file format. It now takes a `cache_key=` keyword from its
caller, and the netCDF loader passes `repr(proxy)` — byte-for-byte the
key computed before.

## Behaviour changes

None intended, and the existing suite passes unchanged.

The one visible difference: `iris.fileformats.netcdf.loader.CHUNK_CONTROL`
and `.ChunkControl` now emit an `IrisDeprecation` when read. They still
resolve, to the *same objects*, so `with CHUNK_CONTROL.set(...)` reached
through the old path still chunks. The user manual points at the new
path.

## Five things a reviewer will want stated

1. **`DEBUG` deliberately did not move**, even though its only reader
   did. It is a flag you set by assignment, and a module `__getattr__`
   can forward a read but cannot intercept a write — PEP 562 gives
   modules no `__setattr__`. Forwarding it would have left
   `netcdf.loader.DEBUG = True` succeeding and doing nothing. So it
   stays defined where it is and `_load_cube_inner` reads it back
   through the module. `CHUNK_CONTROL` and `ChunkControl` are objects,
   used through context managers and never rebound, so forwarding them
   is safe.

2. **`CHUNK_CONTROL.from_file()` still loads small unchunked cubes.**
   The `KeyError` it raises for an unchunked data variable sits *behind*
   the "small enough to read whole" shortcut, so a small contiguous cube
   loads today. The tidier-looking refactor — hoisting that check up
   into the CF layer, which is where the "is this the cube's data
   variable" fact lives — would have broken that. The policy callable
   exists so the check can stay where it is, and there is now a test
   that loads exactly such a cube.

3. **Nothing changed about which attributes reach `cube.attributes`.**
   `read_data` reads `_FillValue`, `scale_factor` and `add_offset` from
   the storage object's attribute mapping, which does not track reads,
   where the old code read them from the `CFVariable`'s mapping, which
   does. Safe for two independent reasons — all four reserved names are
   pre-seeded as read in `_CF_ATTRS_IGNORE`, *and* filtered by
   `saver._CF_ATTRS` — and there is a test comparing `cf_attrs_unused()`
   across a `read_data` call rather than relying on either.

4. **The dask array cache still works.** A cache miss is invisible
   except as slowness, so there are tests asserting the exact key tuple,
   and that a second call with the same key does not rebuild the array.

5. **ncdata's emulation hook still works.** An emulated variable (#4994)
   returns its own array with no proxy built; there are now tests saying
   so directly, where before it was covered only through a full load.
````
