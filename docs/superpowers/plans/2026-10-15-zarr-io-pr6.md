**Goal:** Make `iris.save(cubes, "out.zarr")` write a CF-conforming Zarr version 3 store, by adding a write path to the `ZarrDataset` PR 4 built and a `Saver` subclassing the `CFSaver` PR 5 extracted.

**Architecture:** PR 5 left `cf/saver.py` holding every format-agnostic part of saving a cube — dimension naming, coordinate, bounds, mesh, cell-measure and grid-mapping variables, attribute compliance, lazy write collection — driven through the `CFDataset` interface and four hooks. PR 4 left `zarr/_dataset.py` holding a read-only `ZarrDataset` whose write members raise `NotImplementedError`. This plan fills in those members, adds a fifth hook for grid mappings so that nothing in generic code reaches for a netCDF4 object, and adds `zarr/saver.py`: a `Saver` that opens a store, a `save()` that takes Zarr's own storage vocabulary, and a `delayed_completion()` that returns a real `Delayed` owning the final metadata consolidation.

**Tech Stack:** Python 3.12–3.14, zarr-python ≥3.0.8, NumPy, Dask, xarray (test-only, for cross-reader conformance), pytest + pytest-mock, pre-commit (ruff, numpydoc, mypy, sort-all, and the repository's local hooks), Sphinx.

## 2. Git strategy: a branch over two unmerged pull requests

PR 6 needs both of its predecessors in one tree. It edits `zarr/_dataset.py`,
which exists only on PR 4, and it subclasses `CFSaver`, which exists only on
PR 5. Neither has merged.

So `zarr-io-pr-4-5-base` carries a merge of the two, and `zarr-io-pr-6`
branches from it. The merge commit, `52c478bf9`, resolved five conflicts and
recorded two things neither branch could have had on its own; read it before
starting, because one of them is a gap that will reappear:

> `ZarrDataset.supports_dtype`, the abstract method PR 5 adds to `CFDataset`
> after PR 4 wrote `ZarrDataset`. Both Zarr versions hold every NumPy numeric
> dtype, so it answers `True`. **Whichever of PR 4 and PR 5 rebases second must
> carry this**, or `ZarrDataset` stays abstract and every Zarr test errors.

That method is therefore *not* part of PR 6's diff, even though PR 6's branch
contains it. The same goes for every other line of the merge commit.

**When PR 4 and PR 5 have both landed in `brownfield`:**

```bash
git fetch upstream brownfield
git rebase --onto upstream/brownfield zarr-io-pr-4-5-base zarr-io-pr-6
```

That replays PR 6's own commits and drops the merge, which is why the merge is
a separate branch rather than the first commit of this one. Expect conflicts
only where review changed PR 4's `ZarrDataset` or PR 5's `CFSaver` hooks under
this work.

**Opening the pull request before that rebase is possible** means GitHub would
show PR 4's and PR 5's diffs inside PR 6. Open it as a draft against
`brownfield` only once at least one predecessor has landed, or open it against
whichever predecessor branch is still outstanding and retarget later. The
pull-request body says which it is.

## 3. Findings that refine the spec

Numbered so that tasks can cite them. Each is something checked against the
code or against zarr-python 3.4.1 and xarray 2026.9.0, not something the spec
already says.

**F1. The base is green, and the suite is the proof.** `11188 passed, 59
skipped` across `lib/iris/tests/unit` and `lib/iris/tests/integration` on
`52c478bf9`. Any failure outside the files a task touches is a rebase artefact,
not a bug this plan introduced.

**F2. Grid mappings need a fifth hook, and the body of the method does not
change.** `CFSaver._add_grid_mapping_to_dataset` binds
`grid_variable = cf_var_grid.variable` and then makes **63** plain attribute
assignments to it. `.variable` is netCDF4's own object; `ZarrDatasetVariable`
has no such member, so a Zarr save of any cube with a coord system raises
`AttributeError` today. Q8 refuses to regularise the encoding in this
programme, because routing those 63 through `.attributes` changes what lands in
a netCDF file — `crs_wkt` is `NC_STRING` while `grid_mapping_name` is
`NC_CHAR`. The resolution is one hook, `_grid_mapping_writer(cf_var)`, and one
changed line in the 230-line method. netCDF returns `cf_var.variable`, so its
output is unchanged byte for byte. The base returns an adapter whose
`__setattr__` writes into `cf_var.attributes`. Decided with the user,
2026-10-15.

**F3. `_attribute_handlers` moves to `cf/`, in this pull request.** Spec §12.4
assigns it to PR 6: `cf/saver.py` imports `ATTRIBUTE_HANDLERS` from the netCDF
package, which imports `cf.saver` back, and the cycle survives only because
`_attribute_handlers` imports nothing from `iris.fileformats.cf`. Two source
files and four test files name it. It is private — no deprecation alias is
owed. It is the first task, and its own commit, so that the relocation and the
behaviour work stay separately reviewable. Decided with the user, 2026-10-15.

**F4. `zarr/_encode.py` is a new module the spec's §4.1 layout does not list.**
The write side needs the same kind of pure value conversion the read side has
in `_decode.py`: attributes to JSON-native types, `_FillValue` to its
dtype-dependent encoding, masked arrays to filled ones. Putting them in
`_dataset.py` would push a module that is already 780 lines before any write
code well past the ~1000-line aim in `lib/iris/AGENTS.md`, and would mix pure
functions in with the zarr-python calls, which is what makes `_decode.py`
unit-testable without a store. Decided with the user, 2026-10-15.

**F5. xarray goes in the requirement files now; the lock files are the human
developer's.** Spec §6 puts xarray in with PR 6. PR 4 already regenerates all
three lock files to add `zarr`, so PR 6 regenerating them guarantees a conflict
and a second slow rebuild on rebase. So: `xarray` is added to the test section
of `requirements/py3{12,13,14}.yml` in this pull request, and
`requirements/locks/*.lock` is left alone for the human developer to regenerate
by hand once PR 4 has landed. The consequence to state in the pull-request
body: **until those locks are regenerated, CI has no xarray, so every
cross-reader conformance test skips.** It is installed in `iris-dev` — one
package, exactly as spec §6 measured — so the tests run locally while the work
is being done. Decided with the user, 2026-10-15.

**F6. Every zarr-python and xarray fact the write path leans on reproduces on
today's versions.** Checked against zarr 3.4.1 and xarray 2026.9.0,
2026-10-15:

| Claim | Result |
|---|---|
| `mode="w-"` on an existing store raises | `FileExistsError: Cannot create '' with mode 'w-' because it already contains data. Use mode 'w' to overwrite.` |
| Creating an array over an existing name raises | `zarr.errors.ContainsArrayError: An array exists in store ... at path 'data'.` |
| A non-JSON attribute value poisons the mapping | `TypeError: Object of type float32 is not JSON serializable`, **and** `dict(group.attrs)` afterwards still contains the rejected value |
| A floating `_FillValue` written as a plain JSON number | xarray's open fails for the **whole dataset**: `TypeError: Failed to decode fill_value: expected str or bytes for dtype float32, got float` |
| The same value written as base64 of `struct.pack("<d", ...)` | xarray opens, and masks the filled points |
| An integer `_FillValue` written as a plain JSON integer | xarray opens, and masks the filled points |
| `dtype=str` | a native variable-length `string` array; xarray reads the values back |
| `dtype="<U5"` | a `fixed_length_utf32` array; xarray reads the values back too |
| `shards=` larger than `chunks=` | `Array.shards` and `Array.chunks` both readable back, so the alignment guard has its two numbers |

**F7. `write_handle()` returns the `ZarrDatasetVariable`, not the
`zarr.Array`.** Spec §4.5 says "`ZarrDatasetVariable` returns its
`zarr.Array`"; PR 4 implemented `return self`, with the reason in its
docstring. Returning `self` is the better answer — the wrapper is what applies
the write-side encoding, and `da.store` only needs `__setitem__` — but it
substitutes a new object for the one the spec checked for picklability. So the
picklability the spec verified of `zarr.Array` must be re-verified of
`ZarrDatasetVariable`, under a `pickle.dumps`/`loads` round trip of the whole
delayed graph, which is what a `distributed` scheduler requires. Task 8 does it.

**F8. `_CUBELIST_SAVER_MODULES` is PR 4's, and lists only netCDF.** PR 4 added
the frozenset at `lib/iris/io/__init__.py:36` with one member,
`"iris.fileformats.netcdf.saver"`, replacing the substring test spec §4.7
describes. `iris.fileformats.zarr.saver` joins it here — `save()` takes a
`CubeList` directly, because a Zarr store holds many arrays and is opened once.
Forgetting this does not raise: `iris.save` would loop over the cubes and call
the Zarr saver once per cube, so every cube after the first would meet a store
that `mode="w-"` refuses. Task 9 pins it.

**F9. The `.zarr` suffix reaches `find_saver` already.** PR 4's §4.7 item 3
teaches `iris.io.find_saver` to match `.zarr` with or without a trailing
separator, so `iris.save(cube, "out.zarr/")` works. What is missing is only the
`_savers` entry that maps the suffix to a module — nothing in the dispatch
needs further teaching.

**F10. `missing_value` must be a plain number, and only `_FillValue` is
base64.** Spec §4.5 exempts "these two attributes" together from the JSON-native
conversion and gives one dtype-dependent rule. Written that way, the two
attributes behave differently in xarray, checked 2026-10-15:

| Attribute, on a `float32` array | xarray's reading |
|---|---|
| `_FillValue` as base64 of `struct.pack("<d", v)` | opens, masks the filled points |
| `_FillValue` as a plain JSON number | **the whole dataset fails to open** |
| `missing_value` as a plain JSON number | opens, masks the filled points |
| `missing_value` as base64 | opens, and **the points are not masked** |

So the rule splits: `_FillValue` takes the dtype-dependent encoding, and
`missing_value` is written as a plain JSON number, or a JSON array of them for
the vector form CF §2.5.1 allows. Iris's own reader accepts either shape for
either attribute (`zarr/_decode.py:decode_fill_value`), so this is xarray's
requirement, not Iris's — which is precisely the kind of thing the cross-reader
test exists to catch.

**F11. zarr-python's default `fill_value` is `0` for every dtype, floats
included.** Checked on 3.4.1: `f4`, `f8`, `i2`, `i4` and `u1` all report
`fill_value` `0` when `create_array` is not given one. So a masked float cube
saved without a declared fill would write `0.0` into every masked point and
declare nothing — the mask lost, and the data wrong rather than merely missing.
Iris therefore chooses a sentinel whenever the source is masked and the caller
named none: **netCDF's own default fill values, for every dtype** —
`9.9692099683868690e+36` for floating as well as `-32767` for `int16` and
`-2147483647` for `int32` — written as a small table in `_encode.py`. One cube
saved to both formats then declares the same missing value, which is the point.
The table is Iris's own, not netCDF4's: `iris.fileformats.zarr` may not import
netCDF4, and the `check-netcdf4-imports` hook enforces that. The chosen value is
**always** also written as a CF `_FillValue` attribute, so no reader has to know
the table. Decided with the user, 2026-10-15.

Checked on zarr 3.4.1 and xarray 2026.9.0 that the choice round-trips: a
`float32` array filled with `float32(9.9692099683868690e+36)` and carrying a
`_FillValue` of the base64 of the *float64* constant masks correctly in xarray,
because narrowing that constant to `float32` gives back exactly the stored
value. The same holds for `float64`, `int32` and `int16`.

**F12. `create_variable` never sees the data, so the write grid is enforced by
rechunking at write time.** Spec §4.5 says "`create_variable` derives the write
grid from the source's dask chunking by default". It cannot: `CFSaver` calls
`create_variable(name, dtype, dims, fill_value=..., **encoding)` and only later
calls `_lazy_stream_data(data, cf_var)`, so no dask source is in scope when the
array is made. Two halves replace it, both inside the Zarr subclass, and the
invariant comes out the same:

- `Saver.write()` defaults the **data variable's** `chunks` to the cube's own
  lazy chunking (`cube.lazy_data().chunksize`) when the caller gave none. This
  is a subclass-only change — `**encoding` already reaches
  `_create_cf_data_variable` — and it stops zarr's "auto" chunking picking a
  grid unrelated to how the data is held.
- `Saver._backend_write()` rechunks the lazy source to the created array's write
  grid (`shards or chunks`) before collecting it for `da.store`. When the source
  already tiles the grid, `da.rechunk` is a no-op; when the caller forced
  `chunks=` or `shards=` that the source does not tile, this is what makes
  `lock=False` safe. It is also what covers every coordinate, bounds and cell
  measure variable, which get no derived chunking.

**F13. A masked array written straight to a `zarr.Array` raises, confusingly.**
`array[:] = np.ma.masked_array(...)` on zarr 3.4.1 dies inside numpy.ma with
`ValueError: cannot reshape array of size 3 into shape (12,)`, from the bytes
codec's `view(dtype="B")`. So the filling spec §4.5 requires is not an
optimisation to be skipped for real data; without it, every masked save fails
with a message naming neither the cube nor the mask. `ZarrDatasetVariable.__setitem__`
is the one place it can go, because `da.store` hands blocks straight to it.

```python
class _GridMappingAttributeWriter:
    """An assignment target that writes into a variable's attributes.

    :meth:`CFSaver._add_grid_mapping_to_dataset` sets sixty-three CF
    grid-mapping parameters by plain attribute assignment. On netCDF those
    assignments go to the netCDF4 variable itself and have done since long
    before the CF layer existed, and that decides how each one is typed in
    the file. Regularising it is its own piece of work -- see Q8 in §12.3 of
    the native Zarr I/O design,
    ``docs/superpowers/specs/2026-09-21-zarr-io-design.md``. Every other store
    needs them to arrive in the ``attributes`` mapping instead, and this is the
    object that puts them there.

    def __init__(self, cf_var):
        # Bypass this class's own __setattr__, which would otherwise write
        # the variable into the variable.
        object.__setattr__(self, "_cf_var", cf_var)

    def __setattr__(self, name, value):
        """Write one grid-mapping parameter into the variable's attributes."""
        self._cf_var.attributes[name] = value
```

```python
# Copyright Iris contributors
#
# This file is part of Iris and is released under the BSD license.
# See LICENSE in the root of the repository for full licensing details.
"""Value conversions a Zarr store needs on the way in.

The mirror of :mod:`iris.fileformats.zarr._decode`: pure functions of their
arguments, with no zarr-python call and no Iris object between them, so that
every rule can be tested on a plain value.

**Attribute values are converted before zarr sees them, never after.** A value
zarr's JSON encoder rejects raises, *and stays in the attributes mapping*, so a
caller that converts on failure has already corrupted the store's metadata.

**``_FillValue`` and ``missing_value`` are encoded differently, and the
difference is not Iris's.** On a floating array, released xarray reads
``_FillValue`` through zarr's own fill-value parser, which wants the base64 of
a little-endian ``float64`` and fails the *whole dataset open* on a plain JSON
number. It reads ``missing_value`` as an ordinary attribute, where base64 is a
string that masks nothing. So the first is packed and the second is not. See
§4.5 of the native Zarr I/O design,
``docs/superpowers/specs/2026-09-21-zarr-io-design.md``.

"""

import base64
import struct
from typing import Any

import dask.array as da
import numpy as np

from iris._lazy_data import is_lazy_data

#: The format of a base64 ``_FillValue``: one little-endian float64, whatever
#: the array's own floating width.
_PACKED_DOUBLE = "<d"

#: The fill value each dtype takes when a masked source declares none. These
#: are netCDF's own defaults, so that one cube saved to both formats declares
#: the same missing value. Keyed as ``numpy.dtype.str`` without its byte-order
#: character. Not read from netCDF4: this package may not import it.
DEFAULT_FILL_VALUES: dict[str, Any] = {
    "i1": -127,
    "u1": 255,
    "i2": -32767,
    "u2": 65535,
    "i4": -2147483647,
    "u4": 4294967295,
    "i8": -9223372036854775806,
    "u8": 18446744073709551614,
    "f4": 9.9692099683868690e36,
    "f8": 9.9692099683868690e36,
}


def json_native(value: Any, *, name: str) -> Any:
    """Return `value` as something zarr's JSON encoder accepts.

    Parameters
    ----------
    value : Any
        The attribute value, as the cube holds it.
    name : str
        The attribute's name, for the error message. A failure here is a
        value the user wrote, so the message has to say which one.

    Returns
    -------
    Any
        A JSON-serialisable value: NumPy scalars become Python ones, NumPy
        arrays become lists, ``bytes`` become ``str`` via ASCII, everything
        else is returned unchanged.

    Raises
    ------
    TypeError
        If the value cannot be stored. It is **not** converted to its string
        form: a string that cannot be read back is a worse answer than a
        refusal, and a warning would not stop the save.

    """
    if isinstance(value, bytes):
        try:
            converted = value.decode("ascii")
        except UnicodeDecodeError as exception:
            message = (
                f"Cannot save attribute {name!r}: its bytes are not ascii, "
                "and a Zarr attribute is text."
            )
            raise TypeError(message) from exception
    elif isinstance(value, np.generic):
        converted = value.item()
    elif isinstance(value, np.ndarray):
        converted = value.tolist()
    else:
        converted = value

    try:
        json.dumps(converted)
    except TypeError as exception:
        message = (
            f"Cannot save attribute {name!r}: a value of type "
            f"{type(value).__name__} has no JSON form. Convert it to a number, "
            "a string, or a list of either."
        )
        raise TypeError(message) from exception

    return converted


def encode_fill_value(value: Any, dtype: np.dtype) -> Any:
    """Return a ``_FillValue`` attribute in the encoding readers expect.

    Parameters
    ----------
    value : Any
        The sentinel, in any numeric form.
    dtype : numpy.dtype
        The array's dtype, which decides the encoding.

    Returns
    -------
    str or int or float
        For a floating array, the base64 of the little-endian ``float64``
        form - including for ``float32``, which is what released xarray
        reads. For anything else, a plain JSON value.

    """
    if dtype.kind == "f":
        packed = struct.pack(_PACKED_DOUBLE, float(value))
        return base64.b64encode(packed).decode("ascii")
    return json_native(value, name="_FillValue")


def encode_missing_values(value: Any, dtype: np.dtype) -> Any:
    """Return a ``missing_value`` attribute as plain JSON numbers.

    Never base64, whatever the dtype: xarray reads this attribute as an
    ordinary value, so a packed string there opens cleanly and masks nothing.
    CF section 2.5.1 allows a vector here, so a sequence stays a sequence.

    Parameters
    ----------
    value : Any
        One sentinel, or a sequence of them.
    dtype : numpy.dtype
        The array's dtype. Unused, and named so that the two encoders have
        one signature: a caller choosing between them should not have to
        learn which one wants the dtype.

    Returns
    -------
    int or float or list

    """
    del dtype
    return json_native(value, name="missing_value")


def default_fill_value(dtype: np.dtype) -> np.generic:
    """Return the sentinel to use for a masked source that declares none.

    Parameters
    ----------
    dtype : numpy.dtype
        The array's dtype.

    Returns
    -------
    numpy.generic
        The netCDF default fill for that dtype, as a value of it.

    Raises
    ------
    ValueError
        For a dtype with no entry - a complex or structured array, say,
        which CF cannot express either.

    """
    key = dtype.str[1:]
    if key not in DEFAULT_FILL_VALUES:
        message = (
            f"No default fill value for dtype {dtype}, so masked data of that "
            "type cannot be saved to Zarr. Pass an explicit 'fill_value'."
        )
        raise ValueError(message)
    return dtype.type(DEFAULT_FILL_VALUES[key])


def filled(data, fill_value):
    """Return `data` with any masked points replaced by `fill_value`.

    A Zarr array stores the fill in the data, as spec §4.5 settles: no
    separate mask array. Writing a masked array to one raises inside numpy,
    so this is not optional.

    Parameters
    ----------
    data : numpy.ndarray or dask.array.Array
        Real or lazy, masked or not.
    fill_value : Any
        What replaces the masked points.

    Returns
    -------
    numpy.ndarray or dask.array.Array
        Lazy if `data` was lazy. An unmasked input is returned unchanged,
        not copied.

    """
    if is_lazy_data(data):
        return da.ma.filled(data, fill_value)
    if np.ma.isMaskedArray(data):
        return data.filled(fill_value)
    return data
```

```python
        Zarr has no dimension object: a dimension is a name an array carries
        in its own metadata. So this records the name and size, and
```

```python
    def create_variable(
        self, name: str, dtype, dimensions=(), *, fill_value=None, **encoding
    ) -> "ZarrDatasetVariable":
        """Create and return a new array.

        Parameters
        ----------
        name : str
            The array's name within this group.
        dtype : numpy.dtype or str or type
            The array's dtype. ``str`` itself asks for a variable-length
            string array, which is how this store holds text.
        dimensions : iterable of str, optional
            The names of its dimensions, each already declared by
            :meth:`create_dimension`. Empty for a scalar.
        fill_value : optional
            The CF missing-value sentinel. When given it is written as a
            ``_FillValue`` attribute as well as the array's own fill, because
            on version 3 the attribute is the masking declaration and the
            storage fill is not. When not given, the array takes the netCDF
            default fill for its dtype, and declares nothing: the saver
            declares one if it finds the data is masked.
        **encoding
            Zarr's own storage keywords: ``chunks``, ``shards``,
            ``compressors``, ``filters``, ``serializer``, ``order``.

        Returns
        -------
        :class:`ZarrDatasetVariable`

        Raises
        ------
        ValueError
            If the dataset is read-only, a dimension is undeclared, or `name`
            already exists in this group.
        TypeError
            For a storage keyword this store does not have.

        """
        self._check_writable("create_variable")
        check_encoding_keywords(encoding)

        dtype = dtype if dtype is str else np.dtype(dtype)
        dimensions = tuple(dimensions)
        shape = tuple(self._dimension_size(dimension) for dimension in dimensions)

        if name in self._group:
            message = (
                f"Cannot create {name!r} in the Zarr group {self._location!r}: "
                "it already holds something of that name, and Iris neither "
                "overwrites nor merges into one."
            )
            raise ValueError(message)

        if fill_value is None:
            stored_fill = _encode.default_fill_value(np.dtype(dtype))
        else:
            stored_fill = np.dtype(dtype).type(fill_value)

        array = self._group.create_array(
            name,
            shape=shape,
            dtype=dtype,
            fill_value=stored_fill,
            dimension_names=dimensions or None,
            **encoding,
        )
        variable = ZarrDatasetVariable(array, self._location, self._format)
        if fill_value is not None:
            variable.attributes["_FillValue"] = fill_value

        # Both caches describe a group that has just changed.
        self._variables = None
        self._dimensions = None
        return variable
```

```python
def check_encoding_keywords(encoding) -> None:
    """Raise for any storage keyword a Zarr store does not have.

    Parameters
    ----------
    encoding : dict
        The storage keywords a caller passed.

    Raises
    ------
    TypeError
        Naming each unknown keyword, and the Zarr replacement where there
        is one.

    """
    unknown = set(encoding) - _ZARR_ENCODING_KEYWORDS
    if not unknown:
        return
    lines = []
    for keyword in sorted(unknown):
        replacement = _NETCDF_KEYWORDS.get(keyword)
        if replacement is None:
            lines.append(f"  {keyword}: not a Zarr storage keyword")
        else:
            lines.append(f"  {keyword}: use {replacement}")
    message = (
        "Unknown Zarr storage keyword(s). A Zarr store takes zarr-python's "
        "own keywords, which Iris does not translate netCDF's onto:\n"
        + "\n".join(lines)
    )
    raise TypeError(message)
```

```python
    def finalise(self) -> None:
        """Write consolidated metadata for the whole store.

        One document at the root listing every array and group, which is what
        makes a remote store usable: a reader fetches one object instead of
        one per node. Separate from :meth:`close` because it is a write, and
        a one-shot one - a worker that fills part of a store must not do it,
        since several writers of one metadata object race.

        Always consolidates from the root, even when this dataset is one
        group of the store. A consolidated document that does not mention the
        group just written is what a default reader would believe.

        Raises
        ------
        ValueError
            If this dataset was opened read-only.
        RuntimeError
            If the store cannot be consolidated. Raised rather than returned
            quietly: a store left with stale consolidated metadata hides the
            data just written from every default reader.

        """
        self._check_writable("finalise")
        assert self._group is not None
        with warnings.catch_warnings():
            # zarr-python warns that consolidated metadata is not part of the
            # version 3 specification. Iris asks for it deliberately, and the
            # user cannot act on it.
            warnings.filterwarnings(
                "ignore",
                message="Consolidated metadata is currently not part",
                category=UserWarning,
            )
            try:
                zarr.consolidate_metadata(self._group.store)
            except Exception as exception:
                message = (
                    f"Could not consolidate the metadata of the Zarr store "
                    f"{self._location!r}. The data written is in the store, but "
                    "a reader that uses consolidated metadata may not see it."
                )
                raise RuntimeError(message) from exception
```

```python
# Copyright Iris contributors
#
# This file is part of Iris and is released under the BSD license.
# See LICENSE in the root of the repository for full licensing details.
"""Save cubes to a Zarr store.

.. z_reference:: iris.fileformats.zarr.saver
   :tags: topic_load_save

   API reference

Writes Zarr version 3 stores. The CF work - dimension names, coordinate,
bounds, mesh and grid-mapping variables, attribute compliance - belongs to
:class:`iris.fileformats.cf.saver.CFSaver`, which this builds on. What is here
is what a Zarr store does differently: it is created rather than opened, it
holds text natively, and it finishes with a consolidated metadata document.

**The storage keywords are zarr-python's own**: ``chunks``, ``shards``,
``compressors``, ``filters``, ``serializer``. A netCDF keyword raises and names
the Zarr replacement. Translating ``zlib=True`` onto a Blosc codec would sell a
false equivalence, and would hand this new API the shape the netCDF saver is
stuck with. See §4.5 of the native Zarr I/O design,
``docs/superpowers/specs/2026-09-21-zarr-io-design.md``.

**The default mode is ``"w-"``**, which refuses an existing target, where the
netCDF saver clobbers one. A Zarr clobber is many non-atomic deletes, so an
interrupted one destroys the old store without completing the new.

"""

from pathlib import Path

import iris
from iris.cube import CubeList
from iris.fileformats.cf import saver as cf_saver
from iris.fileformats.cf.saver import CFSaver

from ._dataset import ZarrDataset, check_encoding_keywords

__all__ = ["Saver", "save"]


class Saver(CFSaver):
    """A manager for saving cubes to a Zarr store."""

    def __init__(
        self,
        filename,
        compute=True,
        *,
        mode=None,
        group=None,
        consolidate_metadata=True,
    ):
        """Manage saving cubes into a Zarr store.

        Parameters
        ----------
        filename : str or pathlib.Path
            The store's path or URL. A URL is handed to zarr-python
            unaltered.
        compute : bool, default=True
            If ``True``, lazy data is written and the metadata consolidated
            on exit from the saver context. If ``False``, those writes are
            returned as a :class:`~dask.delayed.Delayed` by
            :meth:`delayed_completion`, which also owns the consolidation.
        mode : str, optional
            One of ``"w-"``, ``"w"``, ``"a"`` or ``"r+"``. The default is
            ``"w-"``, which refuses an existing target, or ``"a"`` when
            `group` is given, since adding a group to a store means the store
            may already be there.
        group : str, optional
            A ``/``-separated path to a group within the store. The root
            group by default.
        consolidate_metadata : bool, default=True
            Whether to write a consolidated metadata document at the root
            when the save completes. Consolidation is what makes a remote
            store usable; declining it suits a store that will be added to
            again before anyone reads it.

        Examples
        --------
        >>> import iris  # doctest: +SKIP
        >>> from iris.fileformats.zarr.saver import Saver  # doctest: +SKIP
        >>> with Saver("out.zarr") as saver:  # doctest: +SKIP
        ...     for cube in cubes:  # doctest: +SKIP
        ...         saver.write(cube)  # doctest: +SKIP

        """
        if mode is None:
            mode = "a" if group is not None else "w-"
        dataset = ZarrDataset(filename, mode=mode, group=group)
        super().__init__(dataset, compute=compute)
        #: Whether the completed store gets a consolidated metadata document.
        self.consolidate_metadata = consolidate_metadata

    def write(self, cube, *args, **kwargs):
        """Write a cube into the store.

        Takes what :meth:`iris.fileformats.cf.saver.CFSaver.write` takes,
        with Zarr's storage keywords in ``**encoding``. ``chunks`` defaults to
        the cube's own lazy chunking, so that the data is written in the shape
        it is held in, and so that the dask source tiles the array's write grid
        without being rechunked.

        """
        if "chunks" not in kwargs and cube.has_lazy_data():
            kwargs["chunks"] = cube.lazy_data().chunksize
        super().write(cube, *args, **kwargs)

    def _create_string_variable(
        self, cube_or_mesh, cf_name, element, element_dims, data
    ):
        """Create a variable-length string array.

        Zarr has a string type, so unlike netCDF there is no trailing
        character dimension to invent and `element_dims` is left alone.

        Parameters
        ----------
        cube_or_mesh : :class:`iris.cube.Cube` or :class:`iris.mesh.MeshXY`
            The Cube or Mesh being saved. Unused here.
        cf_name : str
            The name the variable is created with.
        element : :class:`iris.coords._DimensionalMetadata`
            The element being saved. Unused here.
        element_dims : list of str
            The variable's dimension names. **Not** appended to.
        data : :class:`numpy.ndarray`
            The string values. Unused here: a Zarr string array has no width.

        Returns
        -------
        :class:`~iris.fileformats.zarr._dataset.ZarrDatasetVariable`

        """
        return self._dataset.create_variable(cf_name, str, element_dims)


def save(
    cube,
    filename,
    *,
    mode=None,
    group=None,
    consolidate_metadata=True,
    local_keys=None,
    fill_value=None,
    packing=None,
    compute=True,
    **encoding,
):
    """Save cube(s) to a Zarr store.

    Parameters
    ----------
    cube : :class:`iris.cube.Cube` or :class:`iris.cube.CubeList`
        The cube, or cubes, to save. A whole :class:`~iris.cube.CubeList`
        goes into one store, which is opened once.
    filename : str or pathlib.Path
        The store's path or URL.
    mode : str, optional
        See :class:`Saver`. ``"w-"`` by default, ``"a"`` when `group` is
        given.
    group : str, optional
        A ``/``-separated path to a group within the store.
    consolidate_metadata : bool, default=True
        See :class:`Saver`.
    local_keys : iterable of str, optional
        Cube attribute names that become attributes of the data variable
        rather than global attributes.
    fill_value : optional
        The value of the data variable's ``_FillValue`` attribute, and of the
        array's own fill. One value, or one per cube.
    packing : type or str or dict or list, optional
        How to pack the data, if at all. See
        :meth:`iris.fileformats.netcdf.saver.Saver.write`.
    compute : bool, default=True
        If ``False``, returns a :class:`~dask.delayed.Delayed` that completes
        the store when computed, instead of writing lazy data here.
    **encoding
        Zarr's own storage keywords for the data variable: ``chunks``,
        ``shards``, ``compressors``, ``filters``, ``serializer``, ``order``.
        A netCDF keyword raises :class:`TypeError` naming the Zarr
        equivalent.

    Returns
    -------
    None or :class:`dask.delayed.Delayed`
        A ``Delayed`` if `compute` is ``False``, otherwise ``None``.

    Notes
    -----
    An interrupted save leaves a partial store. Iris offers no rollback: a
    directory rename is atomic on a local filesystem but has no equivalent on
    an object store, so the guarantee would evaporate where Zarr is most used.

    """
    # Validated before anything is created, so that a mistyped keyword does
    # not leave an empty store behind.
    check_encoding_keywords(encoding)

    cubes = CubeList([cube]) if isinstance(cube, iris.cube.Cube) else CubeList(cube)
    fill_values = _per_cube(fill_value, len(cubes), "fill_value")
    packspecs = _per_cube(packing, len(cubes), "packing")

    with Saver(
        filename,
        compute=compute,
        mode=mode,
        group=group,
        consolidate_metadata=consolidate_metadata,
    ) as saver:
        for one, packspec, one_fill in zip(cubes, packspecs, fill_values):
            saver.write(
                one,
                local_keys=local_keys,
                packing=packspec,
                fill_value=one_fill,
                **encoding,
            )

        conventions = cf_saver.CF_CONVENTIONS_VERSION
        if iris.FUTURE.save_split_attrs:
            saver.update_global_attributes({"Conventions": conventions})
        else:
            saver.update_global_attributes(Conventions=conventions)

    return None if compute else saver.delayed_completion()
```

```python
def _per_cube(value, count, name):
    """Return one `value` per cube, from one value or a sequence of them."""
    if isinstance(value, (list, tuple)):
        if len(value) != count:
            message = (
                f"If {name} is a sequence, it must have one element per cube: "
                f"got {len(value)} for {count} cubes."
            )
            raise ValueError(message)
        return list(value)
    return [value] * count
```
