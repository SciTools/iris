# Zarr I/O PR 2.5 — Deprecate `CFVariable.__getattr__` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `CFVariable.__getattr__` warn under `IrisDeprecation` on every CF
attribute it resolves, and move the last four reads inside Iris that would
trigger it onto `CFVariable.attributes`, so a normal load stays silent.

**Architecture:** `CFVariable.__getattr__` already resolves against
`self.attributes` and falls back to the backing netCDF4 object. This adds a
`warn_deprecated` call on the `self.attributes` hit path only, leaves the
fallback's own warning alone, and leaves the miss path silent. Four call sites
in `iris.fileformats` still read a CF attribute as an attribute; each becomes a
mapping read, which records the attribute as used exactly as before.

**Tech Stack:** Python, pytest, `iris._deprecation.warn_deprecated`,
`iris.fileformats.cf.dataset.TrackedAttributes`.

**Spec:** [`docs/superpowers/specs/2026-09-21-zarr-io-design.md`](../specs/2026-09-21-zarr-io-design.md)
— §4.3 is the design, §5 "PR 2.5" is the scope, §12.1 is the live record.

## Review Focus

- **A UGRID connectivity variable with no `start_index`.** CF makes it
  optional and `iris.mesh.Connectivity` defaults it to 0, but
  `_build_connectivity` reads it unconditionally. The mesh then fails to
  build, the cube loads without one, and the failure is recorded in
  `iris.loading.LOAD_PROBLEMS` behind an `IrisLoadWarning` — verified by
  deleting the attribute from a saved file. This change alters the exception
  recorded there from `AttributeError` to `KeyError` and nothing a user sees.
  Task 2 pins the user-visible behaviour and opens an issue for the
  underlying bug rather than fixing it here.
- **`getattr(cf_var, "nonesuch", None)` and `hasattr(cf_var, "nonesuch")` from
  outside Iris.** A miss must stay silent and keep returning the default, or
  the deprecation turns a working idiom into noise on every probe. Task 1.
- **Two reads of the same attribute.** The `setattr` cache was removed in
  [#7303](https://github.com/SciTools/iris/pull/7303), so each read warns.
  A test that reads twice and expects one warning would pass only because of
  `__warningregistry__`. Task 1 asserts two.
- **`copy`, `pickle` and numpy probing dunders on a `CFVariable`.** The dunder
  guard runs before the mapping read, so none of them may warn. Task 1.
- **The attributes that reach a loaded cube.** `cf_attrs_unused()` decides
  this, and all four conversions in Task 2 move a read from `__getattr__` to
  the mapping. Task 2 asserts that `bounds`, `climatology`, `cf_role` and
  `start_index` still do not land on the loaded coordinate or connectivity.

```python
class TestDeprecatedAttributeAccess:
    """Reading a CF attribute as an attribute warns; everything else is silent.

    cf_var.units and cf_var.attributes["units"] are the same read. Only the
    spelling that cannot be type-checked is deprecated. Spec section 4.3.
    """

    def test_reading_a_cf_attribute_warns(self, nc_var):
        cf_var = CFVariableSub("foo", nc_var)

        with pytest.warns(IrisDeprecation) as record:
            assert cf_var.coordinates == "x y"

        assert len(record) == 1

    def test_the_warning_names_the_mapping_and_the_key(self, nc_var):
        cf_var = CFVariableSub("foo", nc_var)

        with pytest.warns(
            IrisDeprecation, match=r"cf_var\.attributes\['coordinates'\]"
        ):
            _ = cf_var.coordinates

    def test_the_warning_points_at_the_caller(self, nc_var):
        # stacklevel: a warning reported against _variables.py tells the
        # reader nothing about which of their lines to change.
        cf_var = CFVariableSub("foo", nc_var)

        with pytest.warns(IrisDeprecation) as record:
            _ = cf_var.coordinates

        assert record[0].filename == __file__

    def test_a_warned_read_is_still_recorded(self, nc_var):
        # The warning is additional to the read, not instead of it. What was
        # read decides what reaches the cube.
        cf_var = CFVariableSub("foo", nc_var)

        with pytest.warns(IrisDeprecation):
            _ = cf_var.coordinates

        assert "coordinates" in dict(cf_var.cf_attrs_used())
        assert "coordinates" not in dict(cf_var.cf_attrs_unused())

    def test_every_read_warns(self, nc_var):
        # There is no instance cache to suppress the second one, and a test
        # expecting one warning would pass only through __warningregistry__.
        cf_var = CFVariableSub("foo", nc_var)

        with pytest.warns(IrisDeprecation) as record:
            _ = cf_var.coordinates
            _ = cf_var.coordinates

        assert len(record) == 2

    def test_the_mapping_does_not_warn(self, nc_var):
        cf_var = CFVariableSub("foo", nc_var)

        with warnings.catch_warnings():
            warnings.simplefilter("error", IrisDeprecation)
            assert cf_var.attributes["coordinates"] == "x y"

    def test_a_declared_property_does_not_warn(self, nc_var):
        # A declared property short-circuits __getattr__ entirely.
        cf_var = CFVariableSub("foo", nc_var)

        with warnings.catch_warnings():
            warnings.simplefilter("error", IrisDeprecation)
            assert cf_var.dimensions == ("time", "lat")
            assert cf_var.cf_name == "foo"

    def test_a_missing_attribute_does_not_warn(self, nc_var):
        # getattr(cf_var, "bounds", None) is a deliberate idiom throughout the
        # loading rules. A miss must stay silent and keep its default.
        cf_var = CFVariableSub("foo", nc_var)
        cf_var.cf_data = object()

        with warnings.catch_warnings():
            warnings.simplefilter("error", IrisDeprecation)
            assert getattr(cf_var, "nonesuch", None) is None
            assert not hasattr(cf_var, "nonesuch")

    def test_hasattr_warns_on_a_hit(self, nc_var):
        cf_var = CFVariableSub("foo", nc_var)

        with pytest.warns(IrisDeprecation):
            assert hasattr(cf_var, "coordinates")

    def test_dunder_probes_do_not_warn(self, nc_var):
        # copy, pickle and numpy all probe for dunders, and the file here
        # really does carry one.
        nc_var.attributes = {"__array__": "nonsense"}
        cf_var = CFVariableSub("foo", nc_var)

        with warnings.catch_warnings():
            warnings.simplefilter("error", IrisDeprecation)
            assert not hasattr(cf_var, "__array_interface__")
            assert not hasattr(cf_var, "__array__")
            _ = copy.copy(cf_var)

    def test_the_netcdf_fallback_keeps_its_own_message(self, nc_var):
        # Reaching a netCDF4 member is a different deprecation, worded for a
        # different fix, and issued by the storage object.
        nc_var.deprecated_netcdf_member.return_value = 42
        cf_var = CFVariableSub("foo", nc_var)

        with warnings.catch_warnings():
            warnings.simplefilter("error", IrisDeprecation)
            assert cf_var.not_an_ncattr == 42
```

```python
class TestLoadingIsSilent:
    """A normal load must not reach CFVariable.__getattr__.

    Every CF attribute read inside Iris goes through CFVariable.attributes,
    so the deprecation on __getattr__ fires only for code outside Iris.
    Spec section 4.3.

    The three cubes between them cover the four attributes that reached
    __getattr__ when the deprecation was added: "bounds" and "climatology"
    from the loading rules, "cf_role" and "start_index" from the UGRID
    loader.
    """

    CUBES = {
        "bounded": lambda: stock.simple_2d(with_bounds=True),
        "mesh": sample_mesh_cube,
        "climatology": lambda: stock.climatology_3d(),
    }

    @pytest.fixture(params=sorted(CUBES))
    def saved_file(self, request, tmp_path):
        path = tmp_path / f"{request.param}.nc"
        with iris.FUTURE.context(save_split_attrs=True):
            iris.save(self.CUBES[request.param](), path)
        return path

    def test_load_emits_no_deprecation(self, saved_file):
        with warnings.catch_warnings():
            warnings.simplefilter("error", IrisDeprecation)
            cubes = iris.load(saved_file)

        assert len(cubes) == 1

    def test_a_cf_attribute_read_from_outside_iris_still_warns(self, saved_file):
        # The other half of the deprecation: silence on a load must not mean
        # the accessor has stopped working. All three cubes carry a long_name,
        # and CFVariable declares no property of that name.
        with cf.CFReader(str(saved_file)) as reader:
            (data_var,) = reader.cf_group.data_variables.values()
            with pytest.warns(IrisDeprecation):
                assert data_var.long_name == data_var.attributes.untracked["long_name"]

    @pytest.mark.parametrize(
        "cube_name, coord_name",
        [("bounded", "foo"), ("climatology", "time")],
    )
    def test_a_cf_reserved_attribute_does_not_reach_the_coord(
        self, tmp_path, cube_name, coord_name
    ):
        # "bounds" and "climatology" are consumed by the loading rules.
        # Attribute tracking is what keeps them off the coordinate, and this
        # pins that reading them through the mapping records them as the
        # attribute spelling did.
        path = tmp_path / f"{cube_name}.nc"
        with iris.FUTURE.context(save_split_attrs=True):
            iris.save(self.CUBES[cube_name](), path)

        cube = iris.load_cube(path)

        assert cube.coord(coord_name).attributes == {}

    def test_a_cf_reserved_attribute_does_not_reach_the_connectivity(
        self, tmp_path
    ):
        # "cf_role" and "start_index" are consumed by the UGRID loader.
        path = tmp_path / "mesh.nc"
        with iris.FUTURE.context(save_split_attrs=True):
            iris.save(sample_mesh_cube(), path)

        cube = iris.load_cube(path)

        assert cube.mesh.face_node_connectivity.attributes == {}

    def test_a_connectivity_without_start_index_loses_its_mesh(self, tmp_path):
        """A UGRID file omitting the optional "start_index" loads without a mesh.

        CF-UGRID makes start_index optional with a default of 0, and
        iris.mesh.Connectivity defaults it to 0, but the loader requires it.
        The mesh build fails and is recorded in iris.loading.LOAD_PROBLEMS.
        Pinned because this reads start_index through the attribute mapping
        now - see the issue linked from this test's pull request.
        """
        path = tmp_path / "mesh.nc"
        with iris.FUTURE.context(save_split_attrs=True):
            iris.save(sample_mesh_cube(), path)

        dataset = _thread_safe_nc.DatasetWrapper(str(path), "a")
        try:
            for variable in dataset.variables.values():
                if "start_index" in variable.ncattrs():
                    variable.delncattr("start_index")
        finally:
            dataset.close()

        with pytest.warns(IrisLoadWarning):
            cube = iris.load_cube(path)

        assert cube.mesh is None
```

and the test would pass against any implementation. Propose the correction to
§5 when the branch is reviewed.

already goes through `.attributes` after PR 2. Four did not, which is why
