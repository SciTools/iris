v3.17 (30 Oct 2026)
===================

.. include:: /whatsnew/3.17/highlights.rst

✨ Features
~~~~~~~~~~~

- :fa:`code-pull-request` :pull:`7236`: :user:`mo-AndrewCreswick` added the option to set the step between
  rolling windows in :meth:`iris.cube.Cube.rolling_window()`. (:far:`circle-dot` :issue:`7217`)

- :fa:`code-pull-request` :pull:`7309`: :user:`claude`, :user:`trexfeathers`, :user:`stephenworsley`, :user:`pp-mo`,
  :user:`bjlittle`, and OpenAI's Codex
  added native Zarr support. Iris reads Zarr version 2 and
  version 3 stores and writes version 3, through the same
  :func:`iris.load` and :func:`iris.save` calls as any other format, with
  ``zarr`` an optional dependency. :func:`iris.fileformats.zarr.load_cubes`
  and :func:`iris.fileformats.zarr.save` take a ``group`` keyword for a store
  that holds more than one dataset. (:far:`circle-dot` :issue:`6977`, :far:`circle-dot` :issue:`6979`,
  :far:`circle-dot` :issue:`6980`)

- :fa:`code-pull-request` :pull:`7361`: :user:`ESadek-MO` updated the CF standard names table to version 95.



🐛 Bugs Fixed
~~~~~~~~~~~~~

- :fa:`code-pull-request` :pull:`7253`: :user:`stephenworsley` fixed a bug which caused indexing to fail when
  ``start_index`` was 1. (:far:`circle-dot` :issue:`7246`)

- :fa:`code-pull-request` :pull:`7257`: :user:`stephenworsley` fixed the default value for ``TEST_DATA_DIR``.

- :fa:`code-pull-request` :pull:`7309`: :user:`claude`, :user:`trexfeathers`, :user:`stephenworsley`, :user:`pp-mo`,
  :user:`bjlittle`, and OpenAI's Codex
  fixed the handling of attributes whose name collides with a
  member of the netCDF4 Python API -- ``shape``, ``size``, ``dtype``, ``name``,
  ``dimensions`` and ``mask``. They were silently dropped when saving and
  silently shadowed when loading; they now round-trip.

  :user:`claude`, :user:`trexfeathers`, :user:`stephenworsley`, :user:`pp-mo`,
  :user:`bjlittle`, and OpenAI's Codex
  fixed saving ``int64`` data to ``NETCDF3_64BIT``, which failed
  inside the netCDF C library rather than narrowing the data to ``int32`` as
  the other netCDF 3 formats do. (:far:`circle-dot` :issue:`7337`)

- :fa:`code-pull-request` :pull:`7348`: :user:`syahra712` fixed the error raised when adding a non-cube to a
  :class:`~iris.cube.CubeList`, which showed a literal ``{obj}`` placeholder
  instead of the rejected object. (:fa:`code-pull-request` :pull:`7348`)



🔥 Deprecations
~~~~~~~~~~~~~~~

- :fa:`code-pull-request` :pull:`7309`: :user:`claude`, :user:`trexfeathers`, :user:`stephenworsley`, :user:`pp-mo`,
  :user:`bjlittle`, and OpenAI's Codex
  deprecated reading a CF attribute as an attribute of a
  ``CFVariable`` -- ``cf_var.units`` rather than ``cf_var.attributes["units"]``
  -- and reaching a netCDF4 variable member through one. Both warn on use and
  will be removed in a future release.

  :user:`claude`, :user:`trexfeathers`, :user:`stephenworsley`, :user:`pp-mo`,
  :user:`bjlittle`, and OpenAI's Codex
  relocated six public names out of
  :mod:`iris.fileformats.netcdf` into :mod:`iris.fileformats.cf`, the package
  that now holds the shared CF loading and saving code. The old names still
  work, and warn with their new location.



🔗 Dependencies
~~~~~~~~~~~~~~~

- :fa:`code-pull-request` :pull:`7270`: :user:`trexfeathers` modernised the Iris gallery tests, and set several to skip
  if using the incompatible combination of PROJ>=9.8 and Cartopy<0.26.

- :fa:`code-pull-request` :pull:`7309`: :user:`claude`, :user:`trexfeathers`, :user:`stephenworsley`, :user:`pp-mo`,
  :user:`bjlittle`, and OpenAI's Codex
  added ``zarr`` (>=3.1.0) as an optional dependency, needed
  only to read or write a Zarr store, and ``xarray`` as a test dependency, used
  to check that stores Iris writes are readable by another Zarr reader.
